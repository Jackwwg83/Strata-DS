对设计的含义

  1. 在这类台式机上，decode 速度由内存带宽决定。CPU kernel 已经跑到带宽的 92% 以上，能调的只剩两样：每 token 要搬的专家字节（由量化位宽决定），以及 GPU 命中率。
  2. 位宽直接换速度。2bpw 比 3bpw 快约 1.5 倍，而且基本不用 SSD。这和上游选 Q2_0（2.25bpw）当最快档是同一个道理。代价是质量，需要单独评估。
  3. 上游"一部分未命中专家用 DMA 送到 GPU 算"的机制（pcie_frac），在支持 AVX-512 的机器上不会提高总吞吐，因为它和 CPU 抢同一条内存带宽。在只有 AVX2、核少、CPU 算不满带宽的机器上才有用。这和上游论文的发现一致。
  4. MTP 或 DSpark 的收益会比上游小。CPU 的开销跟着"不同专家的个数"线性增长。窗口里的 token 共用专家时，超过 4 个 token 还会再多一遍。DeepSeek 的专家比 Qwen 大 9 倍，所以 CPU 侧占大头。
  5. GPU 命中率是下一步最关键的未知数。要拿到它，得用整模型跑真实路由。
  6. 待办：① 测 exllamav3 的融合多专家 GPU kernel，加上 CUDA graph；② CPU int8 激活误差（1.84%）对输出质量的影响，以及 15-bit 高精度模式的速度代价；③ 4 条内存插满时的实际内存频率（容器里读不到 dmidecode）。
