## Change and rationale

Only the QK tile is widened: one CTA computes 64 heads by 128 listed KV rows, using 512 threads (16 warps), instead of 64 rows and 256 threads (8 warps). Each warp still owns two FP32 16x16 accumulator fragments. Eight key-warp positions and two 32-head groups cover the 64x128 output tile exactly once. Cooperative Q and K vector loads advance by the new 512-thread QK launch size.

For the ranking shape's 640 listed rows, this reduces the number of QK CTAs per query from ten to five. The logical repeated global Q loads are halved; the KV row loads and QK arithmetic are unchanged. This is a source-level reuse rationale, not a measured memory-traffic or speed claim. The larger shared-memory allocation and block size could offset the benefit; the queue must establish the net result.

Softmax, PV, chunking, and scratch lifetime retain K13-02's implementation. The maximum is floored at -1e30, only unnormalized PV probabilities are rounded to BF16, the denominator retains the FP32 exponential sum plus the sink term, and output is rounded after division. There is no algorithmic reduction in accumulation precision.

## Bounds and graph lifetime

The public bounds remain `m <= 16384`, `n_idx <= 1024`. The 256-query chunk limit retains one fixed 100,728,832-byte scratch allocation per CUDA device (64 MiB scores, 32 MiB BF16 probabilities, and 64 KiB denominators). Allocation happens on the first eager call and is retained for process lifetime; subsequent calls do not allocate or free, copy to/from the host, or synchronize the stream/device. Every launch uses the supplied stream. Separate streams still require caller ordering for the per-device scratch, as in the merged control.

The 1024-column score pitch contains every padded 128-row QK tail. The unchanged softmax masks negative indices and positions outside the actual list, and PV retains 32-row reduction stages. Row order and duplicates are not constrained by the implementation. Row-address multiplication casts to `size_t` before multiplying by the 512-element head dimension.

## Local validation

The unchanged fixed acceptance test, reference `ops.cu`, K3 dependency, and this K13 implementation were compiled and linked for sm_86, sm_89, and sm_120 using NVIDIA CUDA 12.8.93, GCC 12.2, C++17, and `-O3 --ftz=false --prec-div=true --prec-sqrt=true`.

| Architecture | QK registers / user shared bytes | Softmax registers / user shared bytes | PV registers / user shared bytes |

| sm_86 | 64 / 28,160 | 48 / 0 | 80 / 9,728 |
| sm_89 | 64 / 28,160 | 48 / 0 | 80 / 9,728 |
| sm_120 | 62 / 28,160 | 48 / 0 | 62 / 9,728 |

All three K13 kernels have zero stack-frame bytes and zero register spill loads/stores on all three architectures. On sm_120, the compiler adds 1,024 system shared-memory bytes to each of QK and PV, so the cubin resource totals are 29,184 and 10,752 bytes respectively; the table reports ptxas user shared storage. All remain below the 99 KiB per-block limit.

For sm_86, the compiled 64 registers per QK thread permit two 512-thread CTAs within the 65,536-register budget, totaling 32 resident warps, the same register-limited warp count as four 256-thread K13-02 CTAs. This is a resource calculation, not measured occupancy or throughput.
