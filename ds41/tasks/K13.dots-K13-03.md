# K13-03: recompute logits, keep one tile

Branch: `task/K13/dots-K13-03`
Base: `e0d95c294c1fc7096eed5943d0e3e7640fd7cee2` (`origin/feature/ds41`, fetched 2026-10-06 UTC)

## Strategy

One CTA handles one query, 16 heads, and all 512 output dimensions. The grid has
four CTAs per query. All QK and PV products use BF16 tensor-core MMA with FP32
accumulators, supported on sm_86, sm_89, and sm_120.

The first pass recomputes one 64-key score tile at a time and retains only each
head's maximum and unrounded exponential sum. The usual rescaled running sum is
used only for normalization statistics. The second pass repeats exactly the
same QK instructions and dimension order, rounds probabilities against the
completed global maximum, and immediately accumulates that tile's PV product.
No rounded probability or numerator is ever rescaled against a later maximum.

This pays for an additional QK pass to avoid storing the full logits matrix or
allocating global scratch. A CTA uses 29,824 bytes of static shared memory:

- 16 BF16 queries, with padded row strides
- One 64-key by 64-dimension KV slice, with aligned 16-byte XOR-swizzled chunks
- A 16-head by 64-key FP32 score tile, aliased with the BF16 probability tile
- Source pointers, validity bits, and per-head normalization statistics

There is deliberately no double buffering. Every gather has a CTA barrier
before overwriting the KV tile, per-thread `cp.async.wait_group 0`, and a CTA
barrier before readers proceed. The last slice from second-pass QK is reused for
PV before fetching the other seven slices. A separate CTA barrier retires every
FP32 score read before BF16 writes reuse the score/probability union.

## Numerical contract

The actual `ops::sparse_attn` reference computes:

1. `s_j = dot(q_h, kv_j) * scale`, masking every negative index to negative infinity
2. `maximum = max(-1e30, max_j(s_j))`
3. `denominator = sum_j(exp(s_j - maximum)) + exp(sink_h - maximum)` in FP32
4. `P_j = bf16_rn(exp(s_j - maximum))`, with invalid entries zero
5. `output_d = bf16_rn(sum_j(P_j * kv_jd) / denominator)`

In particular, it does **not** round normalized `exp(...) / denominator` to
BF16. The sink affects only the denominator, including the reference's overflow
behavior for a dominating sink. All-invalid and empty lists retain a zero
numerator. Tensor-core and scalar reduction orders are different; GPU numerical
acceptance remains required.

The kernel covers the full header bound of 16,384 queries and every list length
from 0 through 1,024, with tails zero-filled safely. Repeated indices are retained.
Source offsets use `size_t` before multiplication. Negative indices keep the
original KV base and set the async-copy source size to zero; no negative row
pointer is formed.
