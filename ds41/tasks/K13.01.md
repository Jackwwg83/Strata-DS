# K13-01: fused sixteen-head tensor-core attention

## Scope

One CTA handles one query and sixteen of its 64 heads. QK and PV both use
`mma.sync.m16n8k16` with BF16 inputs and FP32 accumulators. The launch has `4*m`
CTAs and does not allocate a global score buffer. Indices are read as supplied;
there is no dependence on window/compressed ordering, uniqueness, causal
padding, or the fixed test's values of `m` and `n_idx`.

QK gathers 64 rows at a time in 128-dimension slices. All logits for the head
tile remain in shared memory until its complete softmax reduction. A union
then reuses the query/logit/KV space for BF16 probabilities and a 64-row,
512-dimension PV tile. Shared storage is 99,392 bytes (97.06 KiB), below the
99 KiB consumer-GPU limit. The first eager call opts into that amount once per
device. Every subsequent call only checks the initialized device and launches
on the supplied stream; there are no device allocations, frees, host copies,
or host synchronizations, and no retained device scratch.

The arithmetic follows `ops::sparse_attn`: the maximum has a -1e30 floor and
excludes the sink, the unnormalized `exp(score - maximum)` is rounded to BF16
before PV, the exponential sum remains FP32, and the final numerator is divided
by that sum plus the sink term. It does not round normalized probabilities.
All-negative lists and zero-length lists follow the reference's behavior.

## Shared-memory lifetime

- Every row publication finishes with a CTA barrier
- Every gather waits for each thread's asynchronous copies and then publishes
  the completed tile with a CTA barrier
- QK finishes reading a slice before its next gather overwrites that slice
- The softmax loads all logits into registers before the union phase-change
  barrier; probability writes cannot race with another head's logit reads
- A barrier publishes the completed probabilities before PV begins
- Each PV tile ends with a barrier before the next tile overwrites its KV data

Global row offsets cast the index to `size_t` before multiplying by 512.
Negative and tail indices copy zero bytes from a safe base address without
adding dimension offsets to that placeholder. A partial 64-row tile is filled
with zero KV values and zero probabilities.

NumPy is used only by this development model, not by the kernel or runtime.
The checks passed:

- 11,264 literal ldmatrix/MMA operand-fragment mappings and unique gathers
- Every `n_idx` from 0 through 1024, including non-tile-aligned lengths
- Negative indices, duplicate listed rows, and symbolic int32 row offsets
- Unique full output ownership through the interface's `m = 16384` endpoint
- Shared-union phase barriers, gather protocol, and per-device setup checks
- 72 BF16/FP32 arithmetic cases, including broad input magnitudes, empty lists,
  duplicate rows, zero queries, and dominant sinks; worst modeled relative L2
  was 0.000110866

An independent read-only review also checked the exact pinned source's tensor
layouts, barriers, ownership, bounds, math, and graph setup, with no blocker.
CPU GEMM accumulation is not a proof of hardware MMA rounding.

There is no CUDA device on the build machine. The linked sm_86 fixed test exits
77 with `no CUDA device: skipped`. Actual acceptance parity, non-default-stream
CUDA-graph replay, and timings are unverified until the GPU queue runs this
branch. No performance result or merge recommendation is claimed here.
