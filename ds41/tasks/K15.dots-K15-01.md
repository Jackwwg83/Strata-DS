# K15-01: one exact-order FP32 SIMT CTA per token

Base: `c19cf821cf1360db4c4b5239497412fe4dfc4319` (`feature/ds41`).
Branch: `task/K15/dots-K15-01`.

## Design

A single launch covers all `m` tokens, one 256-thread CTA per token. Each lane
keeps 24 FP32 dot accumulators and four FP32 norm accumulators. Weights are read
coalesced; input values are reused for all 24 rows within the CTA. This variant
relies on the cache for reuse between tokens and does not implement a token tile.

The dot, norm, coefficient finalization, 20-step Sinkhorn and incoming-coefficient
collapse are fused. The workspace size is zero. There is no persistent state,
allocation, host synchronization, global atomic, cross-CTA barrier or function
attribute change. The caller's stream is used for the only launch.

## Numerical order

- Dot lane `tid` consumes columns `tid + step*256`, for `step=0..79`, as one FP32
  FMA chain. Grouping four phases changes neither the chain nor its order.
- Norm phase `p` belongs to reference lane `tid + p*256`; its 20 FMA terms have
  stride 1024. Warp partials are stored at `p*8 + warp`.
- Both reductions retain shuffle offsets 16, 8, 4, 2, 1, followed by a serial
  ascending sum from positive zero of 8 dot or 32 norm warp totals.
- `__fmul_rn` preserves the reference's FP32 rounding of dot times reciprocal RMS
  before scale/bias. Sigmoid, softmax, epsilons and iteration count match `ops.cu`.
- Sinkhorn uses ordered four-term sums: softmax plus epsilon, initial column
  normalization, then 19 row/column pairs, each denominator including epsilon.
- Collapse uses `pre_in`, four ordered FP32 FMAs, then one BF16 rounding.

## Validation available without a GPU

CUDA 12.8.93 with GCC 12.2.0, C++17, `-O3 --ftz=false --prec-div=true
--prec-sqrt=true`:

| Architecture | Registers | User shared | Cubin shared | Stack / spills |
| --- | ---: | ---: | ---: | ---: |
| sm_86 | 48 | 996 B | 996 B | 0 |
| sm_89 | 48 | 996 B | 996 B | 0 |
| sm_120 | 48 | 996 B | 2,020 B | 0 |

The sm_120 cubin includes 1,024 system shared-memory bytes. All are far below the
99 KiB limit. For all three architectures, the kernel, reference ops, baseline
K7 dependency and unchanged fixed K15 test compiled and linked; matching native
cubins were verified. Running each test returned 77 (`no CUDA device: skipped`).

`src/ds41/kernels/k15/check_numerics.cpp` uses the same accumulation helper as the
CUDA kernel. It independently models the reference reduction and scalar
Sinkhorn. All 338 tokens from the fixed m=1,37,300 seeded cases and 12 adversarial
cases passed bitwise host-model equality for raw dots/norm, all 24 coefficients
and collapsed BF16 output. Adversarial cases include cancellation across phase
boundaries, wide dynamic range, subnormals, sparse data, zero and alternating
signs. This tests every token, not an aggregate coefficient error.

`check_structure.py` verifies ownership and bounds for m=1..16384, the one-launch
stateless path, and generated PTX for all three architectures. PTX retains 24
closed four-phase FP32 FMA chains, four independent norm chains and 20 groups;
there is no local memory. SASS disassembly was unavailable because `nvdisasm`
was not installed; PTX and cubin resource evidence are not runtime proof.

Reproduce the host checks with a C++17 compiler that supports the local CPU:

```sh
g++ -std=c++17 -O3 -ffp-contract=off -mfma -Wno-unknown-pragmas \
  src/ds41/kernels/k15/check_numerics.cpp -o /tmp/k15-check
/tmp/k15-check
python3 src/ds41/kernels/k15/check_structure.py /path/to/k15_hc_prefill.ptx
```
