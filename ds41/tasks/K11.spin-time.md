# K11: the expert pool spins for 10 ms of time before it naps (Linux)

## Change

`third_party/exllamav3_moe/moe_mul1.cpp`, `Pool::worker_loop`, marked as a Strata-DS patch: on Linux an idle worker
spins (with pause) until 10 ms have passed since its last dispatch, then naps 50 us at a time as before. It spun
65536 pauses before. `EXL3_MOE_CPU_SPIN_US` overrides the time. Windows keeps the 65536 pauses and its
`WaitOnAddress` wake.

## Why

65536 pauses last ~0.8 ms on the Ryzen 9 9955HX3D laptop (measured). In the DeepSeek engine the gap between two
layers' calls (the GPU's layer work, SSD reads) is often longer, so the workers napped between layers, and each
call's first phase waited for them to wake:

- kernel bench (real SAGE experts, 2 per call, 16 threads): a call after a 2 ms gap took 498 instead of 362 us;
- in the engine (per-phase times, `EXL3_MOE_CPU_PROF`): prep_gu 95 us per call with 65536 pauses, 16 us with a
  ~13 ms spin.

## Measured (RTX 5090 Laptop, default settings: adaptive RAM tier, prefetch, 256 tokens, fixed continuations)

ms per token, 10 ms spin against `EXL3_MOE_CPU_SPIN_US=800` (the old length), 2 rounds interleaved:

| prompt  | 0.8 ms        | 10 ms         | CPU experts per token |
|---------|---------------|---------------|-----------------------|
| code    | 51.32 / 51.12 | 50.22 / 50.25 | 15.1 -> 12.6 ms       |
| agent   | 55.67 / 57.21 | 53.60 / 54.62 | 17.1 -> 14.1 ms       |
| zh_chat | 52.55 / 52.38 | 50.68 / 50.91 | 14.6 -> 12.1 ms       |

Back-to-back calls (the K11 acceptance benchmark) never reach the nap, so its score does not change. The fixed
`k11_cpu_moe_test` was not run here (its 3bpw pack is on the queue box only); `moe_revfix` (15 cases) passes.

Still open: in the engine the two GEMV phases are 15-35% slower than in the bench (283 / 154 against 241 / 114 us
per call); concurrent DMA and SSD traffic explains part of it (bench: +5% with nonstop DMA, +15% with nonstop SSD
reads, +25% with both).
