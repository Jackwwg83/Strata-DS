# K11-05: static homes with bounded tail stealing, target experiment only

## Disposition

**Target experiment only. No speed or acceptance claim.** Source correctness and synthetic locality checks passed, but the bounded cloud measurements contradicted one another and every cold-mode run was invalid. The authorized decision is one target-queue measurement, not rejection or acceptance based on a favorable cloud pair. Default workers remain unchanged. The corrected target RAM/file tests and actual-engine comparison decide acceptance. No PR, merge, or deployment is requested. K11-04 is not part of this candidate.

Base: `a59f7ec3ebd0bf20796ddd577ac7c20535944375`, including merged K11-01/02 and the corrected reviewer-owned file diagnostic. The public interface and every official test remain unchanged. The production implementation was frozen at local commit `ca7f93a790ce6045d58d032650b980d358c13dc9` before independent review; this note does not change it.

## Change

Only eligible AVX2/AVX-VNNI GEMV phases use the new helper: 1–8 input rows, more than one worker, aligned positive widths, and the original flat-assignment regime (`total <= 4 * participants`). Many-GEMV strided assignment, larger prefill, scalar, single-worker, and all AVX512 paths keep the original policy.

- Home boundaries are the original static contiguous partitions in matrix order
- The first eight bands, or the whole home if smaller, remain reserved to each owner
- Owners claim up to eight contiguous bands from their remaining front
- After finishing its home, an idle worker makes one bounded pass over other homes and may claim up to four bands from each unclaimed tail
- One packed atomic interval prevents owner/thief overlap, including the last band
- Matrix-boundary clipping retains complete eight-tile bands and complete `run_rows` passes
- All original phase barriers, preparation, numerical kernels, wide-row folding, and accumulation order remain unchanged
- State is in the caller's persistent arena, grown/reset by the coordinator outside dispatch; the existing pool mutex serializes forwards
- Requested workers, small-worker setting, defaults, affinity, and pool primitives are unchanged

The reserved prefix intentionally cannot rescue an owner that never runs. Stealing cannot reclaim in-flight faulting work. This is bounded tail recovery, not a global ticket queue.

## Bounded synthetic performance check

Environment: dot cloud Linux x86-64, Intel Xeon Platinum 8573C, nine visible CPUs, eight requested workers, unchanged default affinity, GCC 14.2 `-O3 -std=c++17 -pthread`, AVX-VNNI cap. No other coordinated numerical benchmark ran during the timing window. Host scheduling variability remains uncontrolled.

The scratch file harness uses owned new files, checked writes/fsync, reopened read-only shared mappings, checked advice/remaps, and per-repetition `mincore`, output equality, faults, `/proc/self/io` read bytes, process CPU, and wall time. Warm/PTE conditions require 100% page-cache residency. Cold requires strictly zero resident pages; no near-cold tolerance was substituted. Source arrays remain allocated. These synthetic files are neither the golden pack nor actual SSD/engine acceptance.

Two checked m1 pairs changed sign substantially:

| Mode | Forward-order control / candidate us | Reverse-order control / candidate us |
| --- | ---: | ---: |
| RAM | 7476 / 11906 (+59.3%) | 10048 / 7884 (-21.5%) |
| Warm mmap | 7556 / 6333 (-16.2%) | 7825 / 7981 (+2.0%) |
| PTE-cold | 8025 / 8625 (+7.5%) | 16457 / 8449 (-48.7%) |

All warm/PTE samples had full residency and zero storage read bytes. Each reported run is the median of 21 RAM or nine file forwards. The final reverse-order m8 pair was 73959/72447 us in RAM, 50808/46023 warm, and 49292/47754 PTE-cold. Its synthetic `m1 + m8 / 8` arithmetic improved 12.2%, but this single result is not reproducible evidence or an official score. An earlier exploratory pair also regressed and is preserved in full; its timer included the output comparison, which the final harness moves outside timing.

Every cold-mode run is INVALID because at least one repetition failed strict-zero conditioning, even after up to three checked attempts. Invalid repetitions in the final harness are not timed. All cold logs are retained, including a baseline m8 run with no valid samples; medians of the remaining samples are not accepted as cold performance. No global cache was dropped and no real pack was modified.

Conclusion: do not select the favorable pair, claim no-regression, or diagnose an exact page-fault cause. The branch is offered only for one bounded target experiment. No local retuning or further noisy cloud performance runs followed the publication decision.
