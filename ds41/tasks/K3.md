## What it computes

Interface: `include/strata/ds41/kernels/k3_sparse_attn.hpp` (`sparse_attn_decode`). For each of m queries (1..8):
64 query heads of width 512 attend to n_idx KV rows (n_idx <= 1024; in the model 128 sliding-window rows plus up to
512 compressed rows). All heads share the same KV row (one KV head, as in MLA). Index -1 is an empty slot.

Math, per head (reference: `ops::sparse_attn` in `src/ds41/ops.cu`, which restates `sparse_attn` in DeepSeek's
`kernel.py` / `ds41/proto/torch_kernels.py`):

1. `s_j = (q . kv_j) * scale` in FP32 for valid j; empty j are excluded.
2. `mx = max(max_j s_j, -1e30)`; `p_j = exp(s_j - mx)`; `denom = sum_j p_j + exp(sink_h - mx)`.
3. `o = sum_j bf16(p_j) * kv_j / denom`, output BF16. (P is rounded to BF16 before the PV product.)

An online softmax over tiles is allowed: rounding P relative to a running maximum changes results by much less
than the tolerance.

## Acceptance (`src/ds41/tests/k3_sparse_attn_test.cu`, fixed)

- Relative L2 error against the reference at most 3e-3 in every case (m 1..8, n_idx 128..1024, partly empty).
- Ranking: `score_us = us_m1 + us_m4/4 + us_m8/8` with n_idx = 640.

## Hints

- The KV rows are shared by all 64 heads: load each row once (into shared memory or registers) and use it for all
  heads, for example with BF16 tensor-core MMA (sm_80+), Q[64x512] x K^T.
- For m > 1 the queries have different index lists; a kernel can still process several queries per block.
- Baseline (the file as committed): one simple block-per-head kernel per query.
