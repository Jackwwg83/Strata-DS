# K10 questions and chosen interpretations

1. The interface can describe other tile widths, but K10 requests EXL3 3-bit
   mul1. Use `tile_w == 48` for all three projections and assert on unsupported
   device descriptors. Do not silently interpret another bitrate as 3-bit.
2. Upstream LinearEXL3 has architecture/occupancy-dependent dispatch. The task
   identifies its small-row GEMV path as the golden path. Use narrow CFG=0,
   MMODE=0, FP32 output, mul1 for each routed token/slot, preserving the exact
   upstream GEMV arithmetic. GPU acceptance must establish the error against
   the supplied golden; no parity or latency claim is possible locally.
3. Upstream fused MoE uses FP16 intermediates/routing weights and its own
   activation. K10 specifies FP32 gate/up, BF16 then block-32 FP8 QDQ, and FP32
   routing weights. Batch the GEMV through device jobs and implement precisely
   that intervening pipeline rather than using the upstream fused activation.
4. Vendor-first history versus forbidden .git writes: copy and byte-verify
   upstream first, then patch; retain a reversible patch and checksum manifest
   so the reviewer can commit the actual pristine baseline before adaptation.
5. No error-return field exists. Invalid host arguments/workspace throw before
   launch; invalid device projection dimensions/rate assert on device. Valid
   calls allocate nothing and perform no host synchronization or device query.

These choices do not block implementation. Compile and GPU validation remain
external requirements, not answered questions.
