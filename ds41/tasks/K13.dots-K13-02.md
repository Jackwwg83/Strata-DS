# K13-02: staged tensor-core prefill attention

Status: submitted for the RTX 3060 queue. GPU correctness, graph replay and speed are not yet measured.

Base: `7025587510974316112f3d1af1b559ea4de85dbe` (`feature/ds41`, 2026-10-06).
Branch: `task/K13/dots-K13-02`.

## Approach

Three batched kernels run in order on the supplied stream:

1. QK computes 64 heads by 64 listed rows per CTA. BF16 WMMA inputs, FP32 accumulation, 64-dimension operand stages. A gathered KV row is reused across all 64 heads in that CTA.
2. Softmax uses one warp per head. Its maximum starts at `-1e30`. The unnormalized `exp(score - max)` is rounded to BF16 for PV. The denominator keeps the unrounded FP32 sum and adds `exp(sink - max)`. The sink does not change the maximum or numerator.
3. PV computes 64 heads by 64 output dimensions per CTA, reducing in 32-row operand stages. The numerator accumulates in FP32 and is divided by the FP32 denominator before final BF16 rounding. Warp-private output staging overlays the now-unused operand memory.

This is a staged design, with scores and BF16 probabilities in global scratch. It does not retain all scores in shared memory and does not recompute QK for the PV pass. It trades scratch traffic and kernel launches for smaller CTAs' shared-memory footprints. These are design choices, not a measured performance claim.

## Bounds and graph lifetime

The public bounds are `m <= 16384`, `n_idx <= 1024`. Calls are broken into at most 256-query chunks; all three kernels finish a chunk in stream order before the next chunk reuses scratch. Arbitrary row order, duplicates, negative padding and partial 64/32-row tiles are supported. KV address arithmetic casts the nonnegative row index to `size_t` before multiplying by 512.

The first eager call allocates one fixed 100,728,832-byte buffer (96 MiB + 64 KiB) per CUDA device for K13:

- 64 MiB FP32 scores
- 32 MiB BF16 probabilities
- 64 KiB FP32 denominators

The allocation is retained for process lifetime and never grows with later shapes. Later calls use the retained buffer, with no allocation/free, host/device copy, device synchronization or stream synchronization. All kernel launches use the supplied stream. As with the task's per-device scratch convention, overlapping calls on separate streams must be ordered by the caller; the mutex protects first-call host initialization, not device execution. Actual graph capture/replay still needs the fixed GPU test.

## Local checks

Built with NVIDIA CUDA 12.8.93, C++17, GCC 12.2, `-O3 --ftz=false --prec-div=true --prec-sqrt=true`:

| Target | QK registers / shared bytes | Softmax registers / shared bytes | PV registers / shared bytes |
| --- | --- | --- | --- |
| sm_86 | 64 / 18,688 | 48 / 0 | 80 / 9,728 |
| sm_89 | 64 / 18,688 | 48 / 0 | 80 / 9,728 |
| sm_120 | 64 / 18,688 | 48 / 0 | 62 / 9,728 |

All three targets compile with zero stack frames and zero register spill loads/stores. The unchanged current fixed test, `ops.cu`, K3 dependency and K13 implementation compile and link for all three targets. Executing each binary without a CUDA device returns the documented skip status 77; this is not a GPU pass.

Run the optional host check with:

```sh
OPENBLAS_NUM_THREADS=1 python src/ds41/kernels/k13/check_staged.py
```

It checks every query count 1..16384 and index-list length 0..1024 for chunk/scratch bounds; verifies WMMA tile ownership and load alignment; and exercises 17 CPU numerical models with duplicate, unsorted and padded indices, all-empty lists, negative scale and tile tails. All checks pass. The worst CPU-model relative L2 is `4.5339329e-05`. NumPy is only used by this optional developer check, not the kernel or its build. The CPU model is not a bitwise emulator of hardware WMMA arithmetic.

An independent source review found no blocker to queue submission after checking operand layouts, unique stores, shared-memory barriers, masks, indexing, all query-count bounds and scratch lifetime. This does not replace GPU validation.
