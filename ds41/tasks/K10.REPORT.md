## Purpose and exact controls

add together: K10-02's two-slot register weight ring and K10-03's narrow integer
packed-weight `.cg` load policy. The two-CTA narrow launch bound is retained.

## Change and preservation

Relative to the freshly merged K10-03 runtime, only the register-prefetch
schedule changes: PF becomes 2, while the narrow arithmetic loop and FP16 fold
cadence remain 4. Each ring slot is consumed then refilled two slices ahead;
compile-time `d % PF` indices avoid local-memory indexing. Wide templates keep
their two-step cadence; narrow half-integer templates retain their original
cache policy while using the same two-slot schedule as K10-02.

The packed-weight cache-policy block is exact K10-03: `__ldcg` only for
`CFG == 0 && !HALF`, with original `__ldcs` wide/half-integer fallbacks.
Scalar uint32 widths, four-byte alignment, lane guards and addresses are
unchanged. No new vector-load alignment requirement is introduced.

All four-slice FP16 rounding groups, FP32 folds, trellis/codebook decode, MMA
instructions and order, cross-warp reduction, input/output Hadamards, SiLU,
clamps, BF16/FP8 rounding, empty-slot guards, supplied stream, five launches
and caller workspace are unchanged. No FP32 reassociation is introduced.
There are no new allocations, host transfers, host waits, dependencies or
persistent scratch buffers. Header, fixed tests, reference and CMake remain
unchanged.

## Two-direction ablation

- Exact K10-02 to candidate: after only C++ comment/whitespace normalization,
  the only source change is the exact K10-03 packed-weight cache block
- Exact K10-03 to candidate: byte-identical after the eight explicit schedule
  substitutions audited in `check_host.py`; no arithmetic normalization
- Thirteen other runtime source/header files are byte-identical across both
  exact controls and candidate
- On CUDA 12.8.93, all three architectures' complete K10 PTX from exact K10-02
  and candidate are identical except twelve `ld.global.cs.u32` instructions
  becoming `ld.global.cg.u32`, and translation-unit salts in three unused
  libcudacxx object declarations. Registers, predicates, operands, addresses,
  control flow and all other instructions are not normalized

K10-03 emits sixteen static packed-weight loads; the two-slot schedule emits
twelve. This is a static generated-code count, not fewer dynamic weight reads:
every required word is still loaded exactly once.

## Local validation

CUDA 12.8.93, C++17, `-O3`, cloud compilation only:

| Production narrow GEMV | Registers | Shared/block | Spill stores/loads | Stack |
| --- | ---: | ---: | ---: | ---: |
| sm_86 | 64 | 2,048 B | 0 / 0 B | 0 B |
| sm_89 | 64 | 2,048 B | 0 / 0 B | 0 B |
| sm_120 | 60 | 2,048 B | 0 / 0 B | 8 B |

All production kernels have no spills and use at most 2,048 shared bytes,
well below 99 KiB. The sm_120 stack frame also exists in exact K10-02/03.
The standard three-target preflight passes. The kernel archives plus current
fixed acceptance test and pack reader compile/link on all three architectures;
this is not a full queue CMake build and the binaries were not executed.
Additional all-target template probes confirm `.cg` for narrow integer 2/3/4
bits and `.cs` for wide 3-bit and narrow 2.5-bit fallback instances.

Reproducible host checks:

```
CXX=g++ python3 src/ds41/kernels/k10/check_host.py
CXX=g++ python3 src/ds41/kernels/k10/check_schedule.py
```

They validate all thirteen pristine upstream hashes and a reversible patch
round trip, exact cache/schedule normalization before comparing whole upstream
arithmetic, once-only/in-bounds/aligned weight reads for both legal projection
shapes, workspace layout, all finite nonnegative BF16 scale maxima and C++17
descriptor layout. The source-extracted C++ schedule checks 24,582 narrow/wide,
load-width and tail cases, plus all warp partitions for K=0..32768 step16.
Its independently fixed expected fold cadence rejects wrong ring slot, refill
slot, refill guard, refill slice, shortened FP16 fold and missing-tail mutants.

A separate mutation run regenerated a coherent upstream patch for each mutant,
then reran the actual provenance/arithmetic audit. All ten were rejected:
wrong ring/refill slot, wrong refill guard/slice, shorter/missing-tail fold,
swapped decoder inputs, changed MMA order, reversed reduction and leaking
`.cg` into fallback templates. Thus rejection is not merely stale patch data.
The schedule model is symbolic; it does not simulate tensor-core arithmetic.
Arithmetic preservation is established by the exact source/PTX comparisons,
not by claiming that symbolic loads are a GPU numerical test.
