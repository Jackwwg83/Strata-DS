## What changes

A 32-thread CTA now owns one slot and one 128-element chunk. Each lane loads
one half4 from that token's input, then performs the gate and up transforms with
their separate suh vectors. The workspace still stores both complete transforms
at `[2 * slot][H]` and `[2 * slot + 1][H]`. Both original job descriptors are
written by lane 0 of chunk 0. An inactive slot writes both null descriptors and
returns before reading expert metadata, inputs or scales.

The new preloaded helper is the unchanged vendored
`had_hf_r_128_inner<true, false>` specialization with only its input load hoisted
into the caller. Each invocation receives a separate by-value half4:

1. Multiply input by that projection's suh with `__hmul2`, retaining FP16 rounding
2. Convert FP16 to FP32 and execute the original four-element butterfly order
3. Call the same `shuffle_had_f4x32` with the same lane and full-warp mask
4. Multiply by the same FP32 normalization constant and convert to FP16 with
   `__floats2half2_rn`

The gate transform is completed and stored before the up transform. No
inter-projection arithmetic is shared. In particular, the two suh vectors may
have unrelated signs, magnitudes, zeros and subnormals. `blockIdx.y` still indexes
the full scale vector in half4 units, and only input/output addresses get the
128-element chunk offset. All lanes make both helper calls, so their existing
full-warp shuffle masks remain valid.

The unchanged five launches use the caller's stream and caller-owned workspace.
There is no allocation, free, host synchronization, data readback, process-global
scratch, cooperative launch, atomic output accumulation or output reset. Both
GEMV stages and the activation/down/output stages retain the reviewed K10-01
source. Host argument, workspace-size and alignment guards are unchanged.

## Cost hypothesis and tradeoff

These are static logical counts, not GPU measurements. For topk=6 with every
slot active:

| m | Input CTAs, before -> after | Input x load bytes, before -> after |
|---|---:|---:|
| 1 | 480 -> 240 | 122,880 -> 61,440 |
| 4 | 1,920 -> 960 | 491,520 -> 245,760 |
| 8 | 3,840 -> 1,920 | 983,040 -> 491,520 |

CTA count halves for every mask; inactive CTAs return without loading x in both
versions. Each active slot saves H half loads. Scale loads, transform output
stores, total arithmetic, GEMV weight reads, downstream work and launch count
remain unchanged. Cached reuse across slots can mean less or no reduction in
actual DRAM traffic. The same two transforms now run sequentially within one
CTA, with half as many input-stage CTAs available for scheduling and more
registers per thread. Reduced scheduling parallelism can outweigh the smaller
block count and input-read cost, especially at m=1. A valid same-box queue result
must decide whether this tradeoff helps.
