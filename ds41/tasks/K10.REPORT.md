# K10-01: register-bounded EXL3 load pipeline

## Candidate and measured evidence

Base: `75356589fcea9b33fe8d2a436354100dbcc4a85b` on `feature/ds41`.
Branch: `task/K10/dots-K10-01`.

This candidate makes one executable change: apply the existing narrow GEMV
`__launch_bounds__(512, 2)` register budget to the integer-rate instance as
well as the half-integer instances. The upstream source already explains why
exceeding 64 registers limits the narrow kernel's occupancy. With the K10
raw-job adapter, CUDA 12.8.93 actually allocates 79 registers per thread to the
baseline 3-bit kernel. The new bound lets ptxas reuse registers more tightly
without spilling.

| Architecture | Baseline registers/thread | Candidate registers/thread | Candidate shared bytes/block | Spill stores/loads |
| --- | ---: | ---: | ---: | ---: |
| sm_86 | 79 | 63 | 2048 | 0 / 0 |
| sm_89 | 79 | 63 | 2048 | 0 / 0 |
| sm_120 | 79 | 62 | 2048 | 0 / 0 |

These are actual compiler resource reports, not GPU measurements. Both
sm_120 builds have an 8-byte stack frame, with no register spill loads or
stores. sm_86 and sm_89 have zero-byte stack frames.

At 512 threads/block, the baseline register count prevents two resident
blocks in a 64K-register SM. The candidate fits two blocks, allowing 32
resident warps instead of 16 to hide streaming trellis-load latency. This is
a resource-based performance hypothesis; it is not a measured speedup.

The unchanged input, activation and output kernels use 32/46/39 registers
on sm_86 and sm_89; their shared allocations are 0/1280/512 bytes. No block
uses more than 2048 shared bytes, well below the 99 KiB limit.

## Numerical and interface preservation

- The complete trellis-load/decode, mul1 codebook, MMA, FP16-to-FP32 folding,
  and ordered cross-warp reduction source remains byte-identical to the
  vendored upstream arithmetic
- The 16-way k split, two n tiles/warp, four-stage prefetch ring and
  four-step FP16 fold cadence are unchanged
- Both Hadamards and scaling, FP32 clamps/SiLU/routing weights, BF16 rounding,
  block-32 FP8 QDQ and final FP16 activation cast are unchanged
- The five-launch pipeline, empty-slot handling, ordered accumulation into
  existing output, supplied stream and caller workspace are unchanged
- No allocation, host synchronization, new dependency, new state, format
  conversion, reduced-precision path or shape-specific math was added
- Fixed header, acceptance test, golden generator, CMake and task spec are
  unchanged. Only K10 CI-FILES are modified

An initial compile-only investigation of fixed-shape specialization reduced
down-projection registers to 72 but left gate/up at 79. It did not reach the
two-block register threshold and was fully reverted. It is not part of this
candidate; the retained optimization is only the narrow launch bound.

## Validation performed

1. Real CUDA 12.8.93 C++17 `-O3` compilation passed for sm_86, sm_89 and
   sm_120, with no fast-math flag. Each baseline and candidate was separately
   compiled with `-Xptxas=-v` for the resource comparison above
2. `CXX=g++ python3 src/ds41/kernels/k10/check_host.py` passed: all 13
   pristine vendor hashes, reversible patch round-trip, byte-identical
   arithmetic, include closure, launch/stream/allocation audit, exact
   trellis address coverage for both projections, workspace layout and
   exhaustive finite nonnegative BF16 scale-rounding checks
3. `git diff --check` passed

The vendored `util.cuh` includes cuBLAS status declarations. The isolated
compiler needed the official NVIDIA cuBLAS 12.8.4.1 headers on its include
path; no cuBLAS function is called or runtime library added. The header-only
files were checked against the official NVIDIA conda package manifest and
also matched the official NVIDIA PyPI wheel byte-for-byte. Full CUDA 12.8
installations already provide this header.

The reusable compile helper was extended outside this repository with a
K10 source mapping and that documented header include path. Equivalent
commands from a full CUDA 12.8 installation are:

```sh
nvcc -std=c++17 -O3 -arch=sm_86 -Iinclude -Isrc -Xptxas=-v \
  -c src/ds41/kernels/k10_exl3_moe.cu -o /tmp/k10-sm86.o
# Repeat with -arch=sm_89 and -arch=sm_120.
CXX=g++ python3 src/ds41/kernels/k10/check_host.py
```
