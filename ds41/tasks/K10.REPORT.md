## Single ablation

The K10-01 GEMV launch bound, launcher and every stage before the final output
kernel are retained exactly. The vendor patch and its reverse/forward
provenance checks remain the K10-01 versions. There is no new GEMV transform,
decoder, fold schedule, reduction, activation or quantization math.

Previously `output_had_add` called the upstream FP32 Hadamard, stored four
contiguous values per lane into shared `result[128]`, synchronized the warp,
read four strided values per lane, accumulated them, and synchronized again.
This repeated in slot order for every nonempty slot.

The new `output_hadamard.cuh` is a return-only adaptation of upstream
`had_ff_r_128_inner`: the float4 load, local butterflies, paired shuffles,
normalization multiply and post-scale multiply are byte-identical source.
Only the final FP32 store is replaced with `return v`. The unchanged vendored
helper is the comparison reference. Four contiguous output accumulators remain
in registers across the same ordered loop; no shared spill/read or explicit
warp barrier is needed. The full-mask warp shuffle synchronization remains.

### Ownership proof

For chunk `c`, lane `l` and component `i`, the new destination is
`128*c + 4*l + i`, with `0 <= l < 32`, `0 <= i < 4`. Quotient and remainder
modulo 4 recover a unique lane/component for every chunk column. Chunks
`0..39` partition all 5,120 columns, ending at column 5,119; token blocks
partition rows. The old `l + 32*i` mapping was also bijective. Changing which
lane owns an output does not change the per-coordinate operation sequence.
No atomics, cross-lane output dependencies or duplicate stores are introduced.

Each accumulator starts from that coordinate's existing caller output. Slots
are visited in ascending `j`; the slot index remains `token*topk+j`. Negative
IDs still skip the transform, scale/expert access, scratch read and addition.
Duplicate expert IDs remain separate slots. All-empty output is copied back
bitwise, including negative zero. Scalar output loads/stores deliberately do
not require stronger output alignment than the old kernel.

### Rounding proof

For a fixed coordinate and slot, all Hadamard inputs, butterfly operations,
shuffle operands/order and scale-vector indices are the same. Shared FP32
storage caused no narrowing, but it separated the last multiplication from
`acc += value`. Explicit `__fadd_rn` now keeps that rounding boundary and blocks
multiply-add contraction after inlining the returned float4. All three PTX
outputs confirm separate multiplies followed by four `add.rn.f32` instructions
and no FMA in the final kernel. Slot accumulation is not reassociated.

## Validation

Commands from the repository root:

- `CXX=g++ python3 src/ds41/kernels/k10/check_host.py`
- `python3 src/ds41/kernels/k10/check_output_host.py`
- `python3 src/ds41/kernels/k10/check_output_mutations.py`
- CUDA12.8 `nvcc -std=c++17 -O3 -arch=sm_86` (and sm_89/sm_120), include the
  fixed include/src directories and existing CUDA/cuBLAS header locations
- Direct compile of the unchanged `src/ds41/tests/k10_exl3_moe_test.cu` and
  `src/ds41/pack.cpp`, archive the candidate kernel, link with CUDA runtime
- PTX generation followed by `ptxas -O3 -v` on all three architectures
- `git diff --check`

The original host checks pass: all 13 upstream manifest SHA-256 hashes,
reverse/forward vendor patch roundtrip, unmodified GEMV arithmetic, include
closure, workspace layout/alignment, trellis addresses and all 32,640 finite
nonnegative BF16 scale maxima. The original check defaults to clang++; this
cloud host uses its supported `CXX=g++` override.

The new checker embeds the ACTUAL source of both helpers, the upstream paired
shuffle function, and the candidate output kernel in a C++17 CPU warp emulator.
Only CUDA builtins/types are supplied by the harness. The emulator snapshots
all lanes at each shuffle; it does not independently implement a Hadamard.
Host arithmetic uses IEEE binary16 scale storage and noncontracted FP32 math.
This cannot prove device execution or performance.

Passed coverage:

- 240 bitwise actual-helper comparisons: all 128 basis vectors, random mixed
  signs/magnitudes/subnormals, scale signs and every scale chunk
- 267 bitwise actual-output-kernel cases and 972 live slots: m=1/4/8;
  topk=1/2/6/7/17/32; all 64 masks at six slots; all-empty/full/alternating/
  last-only selections; duplicate IDs; negative IDs -1/-2/-3
- Nonzero and signed-zero initial output, poisoned empty-slot scratch,
  unchanged other tokens/chunks and a 32-float trailing guard region
- All 5,120 output columns have exactly one owner; last lane/chunk included
- Slot/address bounds enumerated for every m/topk pair admitted by the wrapper
- Concrete bit-level witnesses for slot reassociation and FMA contraction
- Ten deliberate mutations rejected: output reset, reverse slots, last-slot
  omission, aliased ownership, wrong last component, empty-scratch read,
  removed rounding boundary, changed butterfly, changed scale chunk and
  altered GEMV launch bound. Temporary copies only; no candidate mutation

Other kernel PTX matches exact K10-01 on all three architectures after removing
only assertion source-line numbers affected by the added include. GEMV source
and its PTX are unchanged. Final output retains the same 20 shuffle
instructions, removes the two `bar.warp.sync` instructions in the slot loop,
and has no shared/local load/store or FMA.
