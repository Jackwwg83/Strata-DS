# K10: routed experts on the GPU from EXL3 weights

CI-TARGETS: ds41_k10_exl3_moe k10_exl3_moe_test
CI-TEST: ./k10_exl3_moe_test
CI-FILES: src/ds41/kernels/k10_exl3_moe.cu src/ds41/kernels/k10/ third_party/exllamav3_gpu/ ds41/tasks/K10.
CI-ISSUE: 7

## Why

Strata keeps the most-used experts in VRAM and computes them on the GPU, while the CPU computes the rest. The engine
needs a GPU kernel for DeepSeek V4.1's EXL3 3-bit (mul1 codebook) experts, without PyTorch. exllamav3 (MIT, Turboderp)
already has optimized EXL3 kernels: reuse them instead of writing new ones.

## What it computes

Interface: `include/strata/ds41/kernels/k10_exl3_moe.hpp` (`exl3_moe_decode`). For m tokens (1..8) and 6 slots each:
`g = W1 x`, `u = W3 x` (FP32), `g = min(g, 10)`, `u = clamp(u, -10, 10)`, `h = bf16(silu(g) * u * w)`, then the FP8
block-32 quantize-dequantize of h (as `ops::act_quant_inplace`), `fp16(h)`, `out += W2 h` (FP32). `W x` means exactly
exllamav3's `LinearEXL3.forward` (input Hadamard with suh, trellis decode with the mul1 codebook, output Hadamard
with svh). The golden data (`ds41/ci/make_k10_golden.py`) is computed with exllamav3's own LinearEXL3 at commit
16a49792 (v1.5.4) on 32 real experts of layer 10.

## How

1. Copy the needed exllamav3 GPU sources (exllamav3/exllamav3_ext/quant/: exl3_gemv*, exl3_gemm*, exl3_dq.cuh,
   codebook.cuh, hadamard*, the comp_units you need, and their headers) from turboderp-org/exllamav3 at commit
   16a49792 into `third_party/exllamav3_gpu/`, unmodified in a first commit, with its LICENSE and a README naming
   the commit (as `third_party/exllamav3_moe/` does for the CPU kernel).
2. Replace the PyTorch types (at::Tensor host wrappers, TORCH_CHECK, c10::Half) with raw-pointer entry points, in
   later commits so the diff shows every change. Do not change the kernels' math.
3. CMake is fixed: compile the vendored .cu files by #including them from `src/ds41/kernels/k10_exl3_moe.cu`
   (unity build) or from files under `src/ds41/kernels/k10/` that it includes.
4. Implement `exl3_moe_decode`: no allocation (use the caller's workspace), no host synchronization, all m tokens
   and slots in as few launches as practical (exllamav3's `exl3_moe` / multi-expert GEMV kernels do this).

## Acceptance (`src/ds41/tests/k10_exl3_moe_test.cu`, fixed; runs on the GPU box with the pack)

- Relative L2 against the exllamav3 golden output at most 5e-3 for m = 1, 4, 8 (one empty slot included).
- Ranking: `score_us = us_m1 + us_m8 / 8`. One token routes to 6 experts: about 80 MB of weights read; at 954 GB/s
  that is about 85 us, the bandwidth limit for m = 1.
- Compiles for sm_86, sm_89, sm_120 (CUDA 12.8), at most 99 KB shared memory per block.

There is no baseline: the committed placeholder computes nothing and fails.
