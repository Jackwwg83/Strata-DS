# K11-01: a VEX-256 AVX-VNNI path for 3-bit CPU experts

Base: `feature/ds41` at `21d229a` (2026-10-05 UTC). Candidate branch: `task/K11/dots-K11-01`.

## What changes

`strata_avxvnni.h` adds a separate 3-bit, unswizzled kernel. A marked patch in `moe_mul1.cpp` selects it only for
AVX-VNNI hardware. It uses the existing packed weights, quantized activation rows, pool, transforms, and output
FMA. The public `moe_mul1.h` and fixed acceptance test are unchanged. No weight copy, repacking, persistent
expanded-weight cache, new dependency, or additional thread is introduced.

The new path combines three related changes:

- VEX-encoded, 256-bit `vpdpbusd` replaces byte-pair summation plus `vpmaddwd` and integer addition
- Four compile-time row counts eliminate the runtime row branches and most accumulator spills
- For a 16-bit state wholly inside its ending packed word, only that word is shifted and masked. The other
  word's contribution would be discarded by `& 0xffff`

The existing scalar, AVX2, AVX-512BW, AVX-512VNNI, and AVX-512VBMI kernel bodies are unchanged. Other integer
and half-integer bitrates continue to use the original AVX2 kernel when the new tier is selected.

## Dispatch safety

The queue owner confirmed `avx_vnni` on the i9-14900K in issue #8. The new tier checks CPUID leaf 7, subleaf 1,
EAX bit 4 separately from AVX512-VNNI. OSXSAVE, AVX, FMA, F16C, AVX2, and XGETBV XMM/YMM state are checked.
XGETBV runs only after OSXSAVE is present, and subleaf 1 is read only when advertised by subleaf 0.

AVX-512 CPUs still take their original higher-priority paths. `EXL3_MOE_CPU_MAX_ISA=avx2` still forces the
original AVX2 kernel. `EXL3_MOE_CPU_MAX_ISA=avxvnni` caps at the new tier only when that instruction is
actually supported; an older AVX-512 CPU without VEX AVX-VNNI falls back to AVX2. This avoids treating the
AVX-VNNI and AVX-512 feature sets as interchangeable.

The separately targetable intrinsic is enabled with GCC 11 or newer on Linux. Other toolchains keep the
existing dispatch and kernels. No project-wide ISA flag is added.

## Exact integer math

For each 16-bit state `s`, let `p = uint32_t(s * 0x83DCD12D)`. The old AVX2 kernel calculates
`bytesum(p) * x8` by summing adjacent unsigned bytes and multiplying the resulting signed 16-bit values by
replicated activation words. The new instruction calculates the same sum directly from unsigned `p` bytes
and the signed activation replicated four times. It uses non-saturating `vpdpbusd`, not `vpdpbusds`.

The maximum absolute uncorrected dot is `1020 * 127 * k`: 663,244,800 at k=5120 and 1,061,191,680 at the
API limit k=8192, both below INT32_MAX. Activation quantization, wide-row splitting/folding, the -510
correction, FP32 FMA, activation clamp, and weighted accumulation are unchanged.

## Measurements before implementation

The baseline was profiled on the available cloud Xeon Platinum 8573C, GCC 14.2, `-O3 -std=c++17 -pthread`,
with the ISA capped to AVX2. This is a development proxy, not the queue's i9-14900K.

For an L1-resident 256-weight K3 tile at m=1, separate microkernels measured 47.5 ns for decode+dot,
42.5 ns for decode+codebook checksum, 31.7 ns for state-extraction checksum, and 12.0 ns for a predecoded
integer dot. These are independent kernels with overlap and checksum overhead, not additive percentages.
Full-shape worker CPU-time profiling placed about 99% of work in the gate/up and down GEMVs.

GCC's baseline assembly already shares gathers across rows: only 12 `vpermd` per K3 tile. It nevertheless
stores m=1 accumulators after every decoded row, and retains shift/OR operations whose results are masked
away. The new m=1 kernel has no inner-loop accumulator spill stores and retains the same 12 permutes.

## Local validation and timing

- Exhaustive arithmetic equality: all 65,536 states with every signed activation from -127 through +127
- Bitwise old/new kernel outputs for rows 1..4, k=16/128/2304/5120 and n=16/128/2304, including partial tile ranges
- Independent state-extraction check: all 768 one-bit inputs, all-zero/all-one, and 1000 random tiles
- Independent maximum-activation matrix check at k=2304/5120, rows 1..4
- Independent dispatch model: 901,120 combinations of feature flags, XCR0, and ISA caps
- Final whole vendor translation unit compiles with GCC 14.2, `-O3 -std=c++17 -pthread`
- Twenty-one bitwise full-forward comparisons on the final object: full H5120/F2304 at m1/m4/m8,
  shared/disjoint expert routes, deliberately wide inputs, signed routing weights, all five original ISA
  caps, and every other supported integer/half-integer bitrate
- Independent whole-object inspection: only VEX `vpdpbusd` in the four new kernels, no EVEX instructions;
  dispatcher and static initialization contain no vector instructions
