Strata-DS 引擎方案

2026-10-05 · 依据：上游 Strata v0.1.39 源码、DeepSeek V4.1 Flash 官方配置与参考代码、两次 Vast 实测 （bench/results/2026-10-05-4090-7950x/、bench/results/2026-10-05-routing/）。本文是待确认的方案，尚未开始写引擎代码。

一页结论

  1. 做什么：fork 上游 Strata，加一条 DeepSeek V4.1 Flash 模型路径。上游的通用机制全部沿用（内存分层、CPU/GPU 每层分工、自适应专家缓存、prefill 流式、SSD 直读、服务层）；模型相关部分（注意力、路由、mHC、Engram、专家格式）重写。
  2. 性能目标（7950X + 128 GB + 4090，2bpw）：decode ≥ 35 tok/s（推算 45），16 GB 卡 ≥ 22 tok/s（推算 29）；8K prompt prefill ≥ 1,500 tok/s。
  3. 决定性能的三件事（来自实测）：每 token 搬的专家字节数（位宽）、GPU 命中率（自适应缓存）、CPU 侧是否跑满内存带宽（exllamav3 的 AVX-512 kernel 已达 92%）。引擎设计全部围绕这三件事。
  4. 第一条纵切（M1）：C++ 引擎用现有 3bpw 权重跑通整模型 decode，逐层数值与原型对齐、贪心输出逐 token 一致。不先铺功能。
  5. 正确性基准：我们自己的原型（官方 model.py 原样导入）就是对照答案，不需要租 8 卡机器。

3. 关键设计决定（都以性能为导向）

#决定理由（实测依据）
D1专家统一用 EXL3 mul1 格式；kernel 不绑位宽（支持 1–8、2.5 等混合位宽）同一套 kernel 跑 3bpw、2bpw、1.59bpw；CPU kernel 实测达内存带宽 92%
D2CPU 侧：8 线程绑物理核，每层一次调用算完所有未命中专家实测 8 线程最快（44–46 GB/s），16/32 线程反而略慢
D3整个 decode 步录成一张 CUDA graph；CPU/GPU 用 doorbell + 自旋标志同步原型的 GPU 单专家 40 µs 主要是 kernel 启动开销；上游用同样办法消掉
D4GPU 专家用融合 kernel：一次调用算一层所有命中专家逐个算要 6 × 40 µs/层；融合后预计降一个数量级（待 M2 实测）
D5稠密层自写 FP8 块缩放 GEMV（寄存器里反量化），不依赖 FP8 硬件3090（sm86）没有 FP8；decode 本来就卡带宽不卡算力。每步读 8.5 GB，4090 上约 9 ms
D6注意力 kernel 共享内存 ≤ 99 KB官方 kernel 需要 141 KB，4090 上跑不了（实测）
D7内存分层按"最热进显存、次热进内存、最冷进 SSD"，以字节为单位规划128 GB 下 2bpw 只有 1.5% 访问落 SSD；3bpw 是 9%（SSD 成瓶颈）
D8prefill 先做精确模式（40 层全跑）；CED 有界重放作为快速模式，过质量门槛再默认开CED 是官方生产用法，prefill 可快约 1 倍；但属于近似，必须先测质量
D9投机解码（DSpark）放到最后，按实测决定开不开窗口 6 时 CPU 专家量是单 token 的 3.8 倍；若平均接受 < 3.8 个 token，CPU 受限配置会变慢
D10所有数值以原型为准：逐层隐藏状态、逐 token 输出、困惑度原型已在 4090 上验证（生成正确，困惑度正常）

4. 2bpw 量化路线（可选：引擎实测后再决定）

2026-10-05 更新：先不自己做量化。引擎开发用现成的 SAGE 1.59bpw（最快）和 coolbho3k 3bpw（质量最好）；引擎不绑位宽，有更好的 2bpw 时直接换权重包。下面是需要时的做法。

没有现成的 DeepSeek V4.1 2bpw TP1 量化；coolbho3k 没有公开量化工具；exllamav3 的转换脚本只支持 V4 架构。我们只量化路由专家（其余权重保持官方 FP8/BF16），步骤：

  1. 量化源：官方原版 FP4 专家（基座仓库，475 GiB，含 Engram）。不从 3bpw 再压缩，避免误差叠加。
  2. 校准：用原型逐层前向，收集每个专家的输入行，累积 Hessian。逐层进行：第 L 层量化完，用量化后的第 L 层算出第 L+1 层的输入（与 exllamav3 的做法一致）。
  3. 量化核心：直接调用 exllamav3 的 quantize_tiles（LDLQ + trellis，mul1 码本），目标约 2.0–2.25bpw，可按层/按矩阵混合位宽。
  4. 质量评估：同一批文档上与原版 FP4 比 KL、top-1 一致率、困惑度；再加中文与编程任务抽查。参照：3bpw KL 0.041，SAGE 1.59bpw KL 0.19。

成本未知：先做"试点"——只量化 1 层，实测 GPU 时间，再外推整模型成本给你确认。粗估整模型 10–30 GPU 小时（≈ $5–15），未经验证。

6. kernel 拆分与 Codex 分工

每个 kernel 任务都附：输入输出形状、数值语义（每一步量化/舍入）、共享内存预算（sm86/sm89 ≤ 99 KB）、对拍测试（以 proto/torch_kernels.py 与官方 model.py 的函数为参考答案，给出容差）。Codex 写代码，测试在 Vast GPU 机器上跑，我审 diff。

7. 验证方式

  • kernel 级：每个 kernel 对拍参考实现，记录相对误差；比照上游的 *_parity 测试组织方式。
  • 模型级：固定 prompt，在原型里导出每层隐藏状态与 logits；引擎逐层比对。贪心输出逐 token 比对。
  • 质量级：28 篇文档困惑度（已有基线）；量化版本额外比 KL 与 top-1。
  • 性能级：固定 7950X + 4090 机型，记录 tok/s、每层 CPU/GPU/SSD 时间、显存命中率；16 GB 用显存上限模拟，128 GB 用内存限制模拟。原始 JSON 与日志全部入库。
  • TDD：改变运行时行为的代码先写测试；每个 bug 修复带回归测试。

8. 仓库与分支

  • 在 GitHub 上 fork Niko1221/Strata（MIT），本地 Strata-DS/ 改为这个 fork 的工作区。
  • DeepSeek 相关代码放独立目录（如 src/ds41/、include/strata/ds41/、tools/ds41/），研究材料放 ds41/（原型、实测数据、文档），尽量不改上游已有文件，方便以后合并上游更新。
  • 分支：main 保护；功能分支 feature/ds41-*；每次提交不超过 5 个文件。
  • 许可：上游 MIT；exllamav3 MIT；DeepSeek 参考代码 MIT；coolbho3k 运行时是 AGPL，不拷贝其代码，只用其公开的 MIT 权重。

9. 风险

风险影响应对
2bpw 质量不够主推配置不成立M5 试点先测质量；退路是 2.25–2.5bpw（速度约 23–29 tok/s / 24 GB）或混合位宽
真实使用的命中率低于测出的 53–60%decode 变慢语料扩充（更多 agent 对话）；按用户自己的使用重建 profile（上游已支持保存学到的 profile）
