Strata-DS 测试报告 v2：DeepSeek V4.1 Flash（3bpw）对标上游 Strata（Qwen）

2026-10-06（晚） · 批量 prefill（按层处理整个提示词）+ 上游的常驻预算和文件层 · 引擎 b8b20f7 / abf1512 · 模型 EXL3 3bpw（专家 190.5 GiB）
一页结论
  • Prefill：长上下文和上游同一数量级。4090 + 120 GiB 内存：32K 1,093、64K 1,018、128K 1,006、256K 797 tok/s；上游跑 Qwen（模型装得进内存）是 2,100 左右（RTX 5070）和 1,300 左右（Strix Halo）。我们是它们的 0.5–0.8 倍。
  • 短上下文还差 4–6 倍（1K 92 对 536，4K 350 对 1,299）：我们每个 token 要算的专家多，而且一个提示词无论长短都要把约 15,000 个专家搬一遍。
  • Decode 6.6–9.0 tok/s，上游 Qwen 是 46–93。差距主要因为 3bpw 的 DS V4.1（205 GB）装不进 128 GB 内存；上游自己的超大模型案例也只有 7–8.5 tok/s，和我们同一水平。
  • 今天的提升（同一张 4090，和早上的报告比）：32K prefill 288 → 1,093（3.8 倍），decode 3.4–5.8 → 6.6–9.0。来自：按层处理整个提示词（每个专家只搬一次）、上游的常驻预算（最热 96 GiB 专家常驻内存）、上游的 O_DIRECT 文件层、更快的 SSD（8.8 GB/s）。
  • 下一步：prefill 现在完全卡在 GPU 计算上。最大两块是路由专家（~45%，K12 v2 交给 Codex）和 hc 混合（~22%，K15 交给 dots）。两块都做完，长上下文预计到 1,600–1,800 tok/s，接近上游。这是推算，待实测。

说明

  • 怎么测的：每个上下文长度跑一次 ds41_generate：批量 prefill 前 L 个 token，再逐个生成 32–64 个 token。prefill 速度 = L ÷ prefill 总时间（含 Engram 读取、专家搬运、显存缓存还原）。测试文本是本仓库文档和源码拼成的固定长文本。
  • 内存：这台机器宿主有 1 TB 内存，测试时用占内存的进程把容器压到 119.9 GiB，模拟 128 GB 的 PC。
  • 256K（259,943 个 token，和上游「262K」同长）：显存只够每段 16K，分 16 段，每段重搬一遍专家，所以比 128K 慢。原因是每个 query 的候选掩码随上下文平方增长；改成按块存位图后可一次处理更长的段（待做）。
  • 正确性沿用 v1 报告的检查：分段与一次处理 nll 差 0.4%，和官方实现的平均差距 0.031；今天的改动（按层处理、Stager/issuer、O_DIRECT）前后，3000 token 的 nll 都是 1.233182，逐位相同。
  • 数据状态：「我们」的数字都是真实运行的实测输出（原始日志在 ds41/bench/results/2026-10-06-m3/epyc7b13-4090-fastssd/）；上游的数字引自上游文档，不是我们复测的。
