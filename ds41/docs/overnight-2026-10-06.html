一页结论

  1. dots 的 GPU kernel 基本都做到位了。今晚合并了 6 个版本：K3-25、K5-14、K7-06、K8-02→K8-07、K10-03。每个都审过代码，都通过了新加的 CUDA graph 检查。解码一步里的 GPU kernel 已经没有任何 host 同步。
  2. M4（3bpw + 内存/SSD 分层）的代码写完并提交了，数值正确（开不开内存层，输出逐字节相同）。但实测有两个发现，和方案的预期不一样：
    • 按 profile 静态选的内存层，在这台 64 GB 机器上没有帮助，甚至更慢。它挤掉了页缓存，而页缓存按「最近用过」保留专家，反而更能跟上当前文本。所以默认改成不开（和上游一样，需要时再手动打开）。
    • 在这台 Intel 机器上，真正的瓶颈是 CPU 专家 kernel 的 AVX2 路径：每个专家约 0.6 ms，只有 7950X（AVX-512）的一半速度。其次才是 SSD。
  3. 速度现状（这台机器）：每 token 约 0.3–0.5 秒，即 2–3 tok/s。这是「64 GB 内存 + 无 AVX-512 的 CPU + 3bpw 190 GB 专家」的组合，离目标很远，原因已经定位清楚。
  4. 针对瓶颈，新开了任务 K11：CPU 专家 kernel 的 AVX2 优化，交给 dots，列为第一优先级。
  5. 需要你决定 3 件事，见最后一节。

读 SSD 的比例几乎不随预算变化。显存已经放了最热的专家，profile 排在后面的那批和当前文本对不太上，而页缓存会跟着文本走。另外，自动预算（64 GiB 里拿出 60 GiB）实测是 552 ms，比不开（357 ms）慢得多。

时间花在哪

  • CPU 专家约占一步的 90%。专家在内存里时，每个约 0.6 ms（22 GB/s）；7950X 用 AVX-512 是 44 GB/s。这台 i9 没有 AVX-512，大部分 Intel 家用 CPU 也没有。
  • 线程数：8 线程（等于大核数）337 ms，16 线程 375 ms，28 线程 360 ms。混合架构上，线程数应该等于大核数。
  • Lookahead 预取：预测命中约 48%，但对速度的影响在噪声范围内（约 3%）。说明瓶颈不在读盘的方式上。
  • GPU kernel 合计约 19 ms/token，在这台机器上不是瓶颈，所以 dots 的 GPU 提速在端到端里看不出来。
