# K5-13: fused tensor scoring and segment-local first histogram

Base: `feature/ds41` at `c8c41ce1f0f4cd08969243d58294a850ee914fd0`.
Only K5 CI-FILES are changed. The public interface and acceptance test are
unchanged.

## Provenance and prerequisite

The packed-score/spare-half representation derives from K5-12
`e90f35a8d8edc08c72b49d344fdf9dd79cc7269f`. Its exact queue result was
reviewed before this implementation was published: **pass**, 71.87 us at 16K
and 253.1 us at 128K, score 325 us, zero reported score mismatches, and full
512/512 overlap. See [the exact result](https://github.com/Jackwwg83/Strata-DS/issues/3#issuecomment-5995060910).

The tensor dot-product sequence and rounded, ordered head reduction derive
from K5-11 `1f3dd904c5f996c9f5226a7d3677c207de2c39c4`. That exact queue
result passed at 128.8 us; see [its result](https://github.com/Jackwwg83/Strata-DS/issues/3#issuecomment-5994861206).
K5-13's timing and numerical acceptance have not been measured locally.

## Storage and ownership proof

For `t >= 2048`, define `P = floor(t / 2048)`. Owner `p` starts at
`b = 2048*p`. Every owner except the last has length 2048; the last has
length `t-b`, between 2048 and 4095. Appending the short remainder to the
previous owner avoids a separate tail histogram without caller capacity.
No storage is padded beyond the actual caller array.

Owner `p` controls caller bytes `[4*b, 4*(b+L))`:

- Its tensor scorer writes packed BF16 bits into `[4*b, 4*b+2*L)`
- Its first histogram uses its spare half `[4*b+2*L, 4*(b+L))`
- The spare half contains `L >= 2048` halfwords; an 8-halfword header plus
  256 64-bit histogram counts needs exactly `8+256*4 = 1032` halfwords
- After both cutoff bytes are selected, the same histogram area stores two
  64-bit partition counts/prefixes, requiring only 8 halfwords
- The global cutoff and tie quota occupy words 0 through 4 of owner 0's
  header, disjoint from every histogram/count write

The scorer grid is `min(P,256)`. CTA `c` processes owners
`c, c+gridDim.x, ...`; these sets are disjoint and cover all owners.
Each owner scores every position once in 64-position tensor tiles. Score
writes and first-histogram writes stay inside that owner's disjoint interval,
regardless of the progress of any other CTA. Packed scores are produced
directly: no initial float array or overlapping global compression exists.

Metadata loads/stores are explicit 16-bit accesses, including four adjacent
halfwords per 64-bit count. A caller pointer needs only float alignment; an
odd-length last owner does not introduce misaligned 64-bit accesses.

A same-stream kernel boundary separates fused production from the first
cutoff reduction. Further boundaries separate second-byte histograms,
cutoff selection, counts, prefixes, emission, and restoration. All metadata
readers finish before restoration. Each restoration CTA snapshots its entire
owner into at most 8192 shared bytes, synchronizes, and only then expands the
snapshot to caller float storage. Thus expansion cannot overwrite another
lane's unread packed value or another owner's metadata. All original BF16
bit patterns are restored, including signed zeros and NaN payloads.

## Numerics and general interface

Every tensor dot accumulates in FP32. Its result rounds to BF16 before ReLU;
each weighted head contribution rounds to BF16; 32 contributions sum in
ascending head order and round to BF16 again. The tensor instruction sequence
and head-reduction expression match K5-11. Masked scores are negative infinity.
The first histogram is computed from those final scores, using the same
signed-zero-canonicalized two-byte ordering as the second radix pass.

Selection retains 64-bit counts, exact cutoff/tie quotas, positional tie
breaking, and ascending output plus offset. The last owner bounds apply to
histogram, count, and emission loops as well as scoring and restoration.
Small inputs use the existing scratch-free selector. Zero/all-position
selection directly produces float scores and avoids packed metadata.

`candidate_blocks` retains the exact K5-12 full-FP32 four-byte radix path,
including arbitrary positive block size, partial final blocks, final-block
promotion, and negative-infinity dropping. Its const score input is never
changed. Source-region hashes protect this path and the small reference scorer.

No allocator, free, host copy, host synchronization, capture detection, global
workspace, or retained mutable process state exists. Eager calls and graph
capture use the same launch path and only the supplied stream. Independent
calls use only their own caller outputs plus per-CTA shared/register storage.

## Completed cloud-only checks

- CUDA 12.8 / C++17 compile passed for sm_86, sm_89, and sm_120
- Fused scorer: 34,944 shared bytes; registers 44/44/40 respectively
- All kernels: at most 48 registers and 34,944 shared bytes on all three targets;
  zero stack bytes, spill stores, and spill loads
- Generated sm_89 PTX: all seven packed-selection/restoration entries load
  caller scores only with 16-bit operations; metadata writes remain 16-bit,
  while emission/restoration use their intended 32-bit output writes
- 20 storage shapes cover every BF16 encoding, odd/merged tails, arbitrary
  owner/store order, poisoned spare halves, guard words, and exact restoration
- 1,048,147 size cases verify owner bounds and exact metadata/header capacity,
  including large int64 sizes
- 505 fused/packed selection cases cover ties, signed zero, infinities,
  all-masked/equal values, arbitrary k, offsets, tails and more than 256 owners
- 450 additional shared-only radix/tie/candidate cases exercise full-FP32
  candidate selection and nondefault block sizes

Run the dependency-free models from the repository root:

```sh
python3 src/ds41/kernels/k5/test_fused_segments.py
python3 src/ds41/kernels/k5/test_selection_model.py
```

These are compile/source/CPU-model checks. They do not establish GPU numerical
acceptance, graph capture/replay, runtime concurrency, or performance. The
unchanged GPU queue remains the acceptance gate.

The large-input pipeline uses eight launches, versus ten in K5-12: both its
float-to-packed pass and separate first histogram disappear. The 2048-position
ownership choice yields eight scoring CTAs at 16K and 64 at 128K, so reduced
grid parallelism may outweigh the saved passes. This is a measured-by-queue
experiment, not a claimed speedup. A 4096-position owner would reduce that
grid further and is not selected in this first implementation.
