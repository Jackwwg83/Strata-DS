# K5-07: vector SIMT scores and caller-storage radix

Base: `feature/ds41` at `bbc6c25ae9d2c07c81526371a174f3350f6f48b6`.

## Score tiles

Eight warps handle 32 keys per tile. Each warp reuses four query values across
four independent keys. The 32-by-128 FP32 query and 32 head weights are shared
within the CTA; a capped grid reuses them over further tiles. Two coalesced
32-bit BF16-pair loads per lane fetch each key once, followed by a lane shuffle
that recovers dimensions `lane + 32*r`. BF16-aligned pointers that are not
32-bit aligned use scalar loads. Masked keys load no key elements and run no
dot products. Inputs of at most 512 positions retain a compact scalar path.

The four FP32 FMAs and XOR reductions preserve the reference operation order.
The dot is rounded to BF16 before ReLU, each weighted head is rounded to BF16,
and the head sum is accumulated in order in FP32 before the final BF16 round.
No BF16 arithmetic stage is omitted or approximated.

## Exact selection without an allocated workspace

For fewer than 4096 positions, one CTA performs two-byte radix selection and
stable position-order emission using only shared memory. At 4096 positions and
above, the existing caller-provided score allocation also carries transient
selection metadata. Each float score is a BF16 value, so its low 16 bits are
zero. The high 16 bits contain the complete numerical result.

The parallel path performs two radix-byte histograms, chooses the exact cutoff,
counts greater/equal positions in 4096-position partitions, scans those counts,
and emits the result in increasing position order. Four 16-bit metadata words
encode each 64-bit count. Ties consume an exact lower-position quota; both zeros
are canonicalized for comparison. An additional kernel restores every touched
low halfword to zero, preserving the score's original high bits.

### Storage ownership and phase ordering

- Score production finishes before metadata use starts, by same-stream ordering
- During all metadata phases, score values are read only with explicit PTX
  `ld.global.u16` from byte offset `4*j+2`; metadata uses only `ld.global.u16`
  and `st.global.u16` at byte offsets `4*j`
- There are no 32-bit loads, stores, or atomics to the score allocation during
  these phases. Histograms use only CTA-local shared-memory 64-bit atomics
- Histograms have disjoint per-CTA metadata regions starting at low-halfword
  index 8. The five state halfwords occupy indices 0 through 4. These ranges
  cannot overlap. All scores' high halfwords remain read-only
- Each chooser runs only after the preceding histogram completes. Counts reuse
  the histogram region only after the final chooser has completed
- The count scan loads each CTA batch before overwriting its own corresponding
  count records. Barriers protect shared scans and batch reuse
- Emission reads the final state and scanned prefixes without changing scores
- Restoration starts in its own kernel only after every emission CTA completes.
  It writes zero only to the metadata span; all other low halves stayed zero

The original bits of masked negative infinity, signed zero, subnormals, and all
BF16 encodings are preserved by this procedure. No application-visible score
is left altered when the stream reaches completion. As with ordinary CUDA
output buffers, callers must not concurrently access outputs before completion.

### Capacity and general sizes

Let `N >= 4096`, `C = ceil(N/4096)`, and `P = min(C, 256)`. The histogram needs
`8 + 1024*P` halfword slots; the count/prefix phase needs `8 + 8*C`. Both fit in
the `N` available low-halfword slots, including partial final partitions. The
metadata span is their maximum. Shorter calls use the shared-only path instead.
Kernel grids use capped grid-stride loops, and counts/prefixes are 64-bit.
`k` is clamped to `[0, N]`; selecting all positions bypasses selection entirely.
There is no maximum-context allocation, input-size-specific answer, or host
inspection of scores, masks, weights, or output values.

Candidate-block selection retains full FP32 score bits and therefore uses the
shared-only four-byte radix path. Block maxima are computed on demand; the
final block receives positive infinity before selection, negative-infinity
blocks are excluded, and ties prefer lower blocks. Arbitrary positive block
sizes and partial final blocks follow the same rules.

## CUDA graph behavior

Eager and captured calls execute identical paths for identical interface
arguments. There are no allocations, frees, host synchronizations, device-host
copies, global mutable storage, events, stream capture checks, or lazy caches.
Only the supplied stream is used. Independent calls have no internal shared
state and may run concurrently when their caller-owned arrays do not overlap.

## Validation

CPU models, neither of which executes a GPU:

```
python src/ds41/kernels/k5/test_selection_model.py
python src/ds41/kernels/k5/test_caller_storage.py
```

The shared-only model checks exact cutoff/tie selection, ascending compaction,
full-FP32 candidate maxima, irregular block sizes, tails, and grid coverage.
The caller-storage model additionally checks all 65536 packed BF16 encodings,
reference-order score stages with masks, metadata phase contents and bounds,
exact score restoration, saturated grids, large counters, and positional output.

CUDA 12.8 C++17 compilation passes for sm_86, sm_89, and sm_120. On sm_89, ptxas
reports 51 registers and 16512 bytes shared memory for vector scores, zero
spills, and at most 2328 shared bytes for selection. All kernels use less than
99 KB shared memory. These are compiler facts, not a performance measurement.
GPU acceptance, graph replay, and timings remain for the unchanged test queue.
