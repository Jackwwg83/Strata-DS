# K5-17: raw MMA with a register-only ordered epilogue

Base: `feature/ds41` at `8d5a1d0e20fd7e3ad672bfde0524ec14e326dcbe`.

Control: K5-11 at `1f3dd904c5f996c9f5226a7d3677c207de2c39c4`,
[RTX 4090 result](https://github.com/Jackwwg83/Strata-DS/issues/3#issuecomment-5994861206):
`us_t16k=44.93`, `us_t128k=83.87`, `score_us=128.8`, passing.

Only the 64-key scorer and its helpers change. The small-input scorer, complete
selector, candidate-block implementation, host dispatch, and stream behavior are
byte-identical to that control. This is an experiment, with no speed claim before
an exact-SHA GPU result.

## Operand and accumulator ownership

Each CTA still has 128 threads and handles 64 keys. Warp `w` handles keys
`16*w .. 16*w+15`. Q and K are staged as the same row-major BF16 arrays as K5-11.
Eight dimension steps execute raw `mma.m16n8k16.row.col.f32.bf16.bf16.f32`.
The two head groups and two key groups require four instructions per step.

The mapping follows the [CUDA 12.8 PTX fragment specification](https://docs.nvidia.com/cuda/archive/12.8.0/parallel-thread-execution/index.html#warp-level-matrix-fragment-mma-16816-float).
For lane `l`, let `g=l/4` and `u=l%4`. The four A registers hold BF16 pairs
at head offsets `g,g+8,g,g+8` and dimension offsets `2*u,2*u,2*u+8,2*u+8`.
A non-transposed `ldmatrix.x4` loads these from four 8-by-8 tiles. The two B
registers hold pairs at key `g` and dimension offsets `2*u,2*u+8`; the physical
row-major key storage is the required column-major B matrix, so x2 is also
non-transposed. Every supplying row starts on a 16-byte boundary.

With the head/key groups incorporated, register `r` of the 16 FP32 accumulators
has the following coordinate:

- head = `16*(r>>3) + 8*((r>>1)&1) + (l>>2)`
- local key = `8*((r>>2)&1) + 2*(l&3) + (r&1)`

This covers all 32-by-16 entries exactly once per warp. Accumulators remain in
registers throughout the eight K steps. Every entry is separately rounded to
BF16, passed through ReLU, multiplied by its own BF16 weight in FP32, then rounded
to BF16. No head combination occurs before these two rounding points.

## Register permutation and ordered sum proof

Initially the five lane bits represent `[head4,head2,head1,key4,key2]` and the
four register-index bits represent `[head16,key8,head8,key1]`, high bit first.
Three exact data permutations exchange these lane/register bit pairs:

1. lane bit 16 with register bit 8
2. lane bit 8 with register bit 4
3. lane bit 4 with register bit 1

Each stage uses eight XOR shuffles and selects, without floating-point arithmetic.
For every lane/register pair, unequal selected bits exchange places and equal bits
stay unchanged. The resulting lane bits are `[head16,key8,key1,key4,key2]`;
register bits are `[head4,head2,head8,head1]`.

Consequently lane `l` owns heads `16*(l/16) .. 16*(l/16)+15` of key
`8*((l>>3)&1)+2*(l&3)+((l>>2)&1)`. Head offset `h` is register
`(h&1) | ((h&8)>>2) | ((h&6)<<1)`.

Lanes 0 through 15 start from positive zero and use explicit `__fadd_rn` in
head order 0 through 15. One full-warp shuffle transfers that running value to
lane `l+16`. That lane continues the same sum with heads 16 through 31, again
using explicit rounded FP32 adds. There is no separately reduced upper-half
partial and no tree reduction. The final value receives the third BF16 rounding.
Sixteen lanes per warp each write one distinct score, with the original mask and
tail semantics. All shuffles precede the output owner, tail, and mask branches.

The CPU model exhaustively checks all 512 coordinates and the permutation,
verifies input load mappings, and compares random epilogues bit-for-bit with
ordered reference addition. A cancellation witness crosses heads 15/16 and
would fail if the two halves were independently reduced and then added.

## Storage, streams, and boundaries

Static scorer shared memory is 24,704 bytes: Q 8,192, K 16,384, weights 128.
This removes the control's 8,192-byte FP32 dots matrix and its second CTA barrier.
The only CTA barrier follows input staging. Input arrays are then read-only;
warp-local MMA, rounding, permutation, and sum require no further CTA barrier.

The same `t<=512` exact small scorer remains. Tensor tiles zero-fill invalid key
rows and never read or write an invalid original position. Arbitrary mask values,
negative head weights, k clamping, signed-zero ties, the -inf mask, lower-index
tie breaking, and ascending output plus offset retain the original behavior.

The complete K5-11 halfword metadata selector and restoration are unchanged;
see `K5-11.md` for their storage-capacity and phase-order proof. There is no
allocation, deallocation, host synchronization, host data copy, mutable global
scratch, or capture-dependent path. Every launch uses the provided stream.

## Validation

Commands from the repository root:

```
python src/ds41/kernels/k5/test_register_epilogue.py
python src/ds41/kernels/k5/test_selection_model.py
python src/ds41/kernels/k5/test_caller_storage.py
python src/ds41/kernels/k5/test_tensor_storage.py [generated-sm89.ptx]
```

CUDA 12.8 C++17 compile-only checks pass for sm_86, sm_89, and sm_120. sm_89
ptxas reports 39 registers and 24,704 shared bytes for the scorer, versus the
control's 46 registers and 32,896 shared bytes. Every kernel has zero spills and
zero stack bytes, and the module has zero mutable global bytes.

The generated sm_89 PTX has 32 raw MMA instructions, 24 permutation shuffles,
one carry shuffle, 32 explicit `add.rn.f32` operations, and one CTA barrier.
There are no scorer shared stores after the staging barrier or local spills.
All eight selector metadata kernels retain 16-bit score accesses.

CPU tests and compilation do not validate actual tensor accumulation, device
races, GPU acceptance, timings, or CUDA graph replay. The raw tensor dot order
may differ from the SIMT reference within the task's tolerance; the BF16 rounding
points and head-addition order are exact. GPU validation remains pending.
