# K5-05: tensor scores and scratch-free selection

Base: `feature/ds41` at `bbc6c25ae9d2c07c81526371a174f3350f6f48b6`.

The score kernel computes 32 heads by 128 positions with BF16 WMMA. Its epilogue
preserves the BF16 rounding after dot, after ReLU times head weight, and after
the FP32 head sum. Candidate masking is fused into that kernel. Small inputs use
the reference warp reduction order. MMA accumulation order may differ within
the task's stated score tolerance.

Key staging and accumulator stores share an overlaid shared-memory allocation.
Aligned global operands use 16-byte loads; unaligned operands have a scalar
fallback. The score grid strides over keys without a context-sized workspace.

## Scratch-free selection and graph behavior

One CTA computes a two-byte radix cutoff from BF16 scores, then emits selected
positions in ascending order. Each emission batch covers 1024 positions: four
parts across eight warps. The first warp scans the 32 part/warp counts, preserving
lower-position ties and the exact tie quota. Candidate block selection uses four
radix bytes to retain every FP32 bit, computes maxima on demand, and follows the
final-block and negative-infinity rules.

All cutoff, histogram, and scan storage is CTA-local shared memory. The only
global writes are caller-provided score/output/candidate arrays. There is no
internal GPU allocation, free, process-global scratch, completion event, pool
setting, capture-ID registry, host synchronization, or host-device copy.
Independent invocations do not share internal mutable storage. Callers still
must avoid racing their own input/output arrays.

Eager calls and captured calls run the same kernels and selection strategy.
The initial experimental fused score/global-histogram design was replaced to
remove its graph-scratch lifetime and serialization assumptions. There is no
special faster benchmark-only eager path.

## Validation

Run the CPU selection model:

```
python src/ds41/kernels/k5/test_selection_model.py
```

It checks radix cutoffs, signed-zero and infinity ties, the CTA's positional
part/warp scan, candidate FP32 maxima, partial blocks, and saturated-grid tails.
This is a mathematical model, not a GPU parity test.

The cloud compiler preflight checks this translation unit using CUDA 12.8 and
C++17 for sm_86, sm_89 and sm_120. Only the unchanged RTX 4090 acceptance queue
can establish GPU parity and `score_us`. No performance claim is made from
compilation or the CPU model.
