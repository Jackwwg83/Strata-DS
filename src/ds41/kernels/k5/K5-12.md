# K5-12: packed-segment caller storage

This branch starts at `feature/ds41` commit
`c8c41ce1f0f4cd08969243d58294a850ee914fd0`. It keeps the score
kernels and scratch-free candidate-block implementation from K5-07 commit
`466796657f` unchanged. K5-11's tensor-score source was inspected but is not
part of this storage-only experiment.

## Storage and ordering

For a segment beginning at position `b` with actual length `L <= 4096`, the
caller owns bytes `[4*b, 4*(b+L))`. One CTA first snapshots all `L` original
BF16-valued floats in 8192 bytes of shared memory, then packs their exact high
16 bits into `[4*b, 4*b+2*L)`. The remaining `[4*b+2*L, 4*(b+L))` holds
contiguous metadata. No segment is padded into caller memory.

The second halves form a logical metadata stream of exactly `t` halfwords,
namely the actual `2*t` bytes freed by packing. A logical halfword `w` maps to
physical halfword `2*b + L + (w % 4096)`, where
`b = (w / 4096) * 4096` and `L = min(4096, t-b)`.

Counts remain 64-bit, serialized through four adjacent 16-bit accesses.
Their width is derived from `sizeof(Count) / sizeof(uint16_t)` with compile-time
ABI checks. No wider alignment than the caller's float pointer is assumed,
including an odd-length final segment. Metadata never aliases the packed
score region.

With `P = ceil(t / 4096)` and `H = min(P, 256)`, the exact required halfwords
are `8 + max(1024*H, 8*P)`. The host checks both phase requirements against
`t` using division before multiplication. Short inputs or insufficient actual
capacity use the original scratch-free selector. Zero and all-position
selection avoid packing.

The two exact radix bytes, 64-bit global counts, signed-zero tie handling,
partition prefixes, and ascending stable emission are preserved. The launch
sequence on the supplied stream is:

1. Original score production
2. Segment packing
3. First histogram and byte choice
4. Second histogram and byte choice
5. Partition counts, exclusive prefixes, and stable output emission
6. Segment restoration

Restoration is a separate launch after **all** metadata consumers finish. Each
CTA snapshots its complete packed segment before expanding any value back to
float. Segments are disjoint; each is owned by one CTA. This permits arbitrary
CTA order without overwriting an unread packed value or live metadata. Original
float bits, including signed zeros and BF16 NaN payloads, are restored exactly.

Eager execution and graph capture use the same pipeline. There is no internal
global scratch, allocation/free, host copy, host synchronization, or device
result read on the host. `candidate_blocks` never uses packed storage and
retains the original full-FP32, four-byte scratch-free selection path.

## Validation completed without a GPU

- CUDA 12.8 compile-only checks passed for sm_86, sm_89, and sm_120
- sm_89 compiler resource report: maximum static shared memory 16,512 bytes;
  pack and restore each use 8192 bytes; no stack/spill stores or loads
- Exact source-region checks confirm K5-07 score math and candidate selection
  are unchanged
- CPU storage model covers 22 sizes, all 65,536 BF16 encodings, partial and odd
  tails, shuffled CTA/store order, guard words, full-slack poisoning, and
  64-bit count serialization
- Capacity model covers 1,050,204 sizes, including every size from 1 through
  1,049,999 and large int64 sizes
- Numerical selection model covers 713 cases: ties, signed zero, infinities,
  masked/all-equal scores, negative offsets, zero/oversized k, the 4096 boundary,
  and more than 256 partitions

Run the dependency-free CPU model from the repository root:

```sh
python3 src/ds41/kernels/k5/packed_segments_model.py
```

These checks do not establish CUDA numerical acceptance, runtime race freedom,
CUDA graph replay correctness, or performance. Those remain for the unchanged
GPU queue tests. The additional packing launch is an intentional cost of the
storage experiment; no speedup is claimed before queue measurement.
