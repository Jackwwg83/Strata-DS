# K5-10: large pipelined BF16 score tiles

Base: `feature/ds41` at `bbc6c25ae9d2c07c81526371a174f3350f6f48b6`.
Only the K5 implementation and its allowed `k5/` support directory change.

## Distinct score design

A 256-thread CTA computes 32 heads by 256 keys. Its eight warps each own 32
keys and four 16-by-16 FP32 accumulator fragments. Two query fragments are
reused across two key fragments at each tensor-core step. The CTA loads the
32-by-128 BF16 query once and reuses it across grid-stride score tiles, with a
maximum of 256 CTAs.

This explores a tile twice as wide as K5-05's x128 design and eight times as
wide as the separate K5-09 x32 experiment. Wider tiles reduce query reloads
per key and CTA scheduling work, but expose fewer independent CTAs on short
inputs and require more per-thread accumulators. These are design tradeoffs,
not measured speedups.

A complete 256-by-128 BF16 key tile occupies 64 KB, so the kernel instead uses
two 256-by-32 BF16 stages, totaling 32 KB. The next reduction-dimension stage
is prefetched with Ampere-compatible `cp.async.cg.shared.global` while WMMA
consumes the current stage. Four 32-dimension chunks cover all 128 dimensions.
Each chunk has two 16-dimension tensor steps. The final wait and CTA barrier
complete every asynchronous copy and matrix load before the staging union is
reused as a 32-by-256 FP32 dot tile.

The entire static shared-memory footprint is 41,344 bytes: 8 KB query, 32 KB
union, 128 bytes weights and 256 bytes live flags. No dynamic shared-memory
opt-in or host-side device-property lookup is required. The key/query pointers
need only BF16 alignment; addresses not aligned to 16 bytes use scalar staging.
Tail and masked vectors are zero-filled, with valid source addresses even for
zero-byte asynchronous copies. The live mask is still applied in the epilogue.

The dot result is rounded to BF16 before ReLU. Each weighted head is rounded
separately to BF16; the 32 heads are accumulated in increasing head order in
FP32 and rounded once more to BF16. Intermediate dot products remain FP32 and
never leave shared memory. The tensor reduction order may differ from the
reference within the fixed task tolerance. Inputs of at most 512 keys retain
the reference SIMT accumulation order.

## Exact allocation-free selection

When `512 <= min(k,t) < t`, the first 512 caller-provided output words temporarily
hold 256 split 64-bit high-byte histogram counters. `cudaMemsetAsync` clears
exactly those words on the supplied stream. Score epilogues produce the first
radix histogram, grouping equal warp bins before each global atomic addition.
Split words respect the public pointer's int32 alignment; low-word overflow
increments the paired high word. Every counter producer finishes before the
consumer kernel starts on the same stream.

One CTA loads all histogram counters into shared memory before repurposing
any output words. It selects the high-byte cutoff, scans scores to select the
exact low-byte cutoff, and counts greater/equal values in consecutive per-thread
intervals. Exclusive prefixes assign increasing-position output ranges, with
an exact quota admitting only the earliest cutoff ties. All writes are within
`min(k,t)` words. Counts are 64-bit and signed zero is canonicalized for ties.
Smaller `k` values use the same shared-only selector without touching output
scratch; `k == t` directly emits all positions. Scores are never used as scratch
and retain their final BF16 float values throughout selection.

Candidate-block maxima are recomputed on demand with all FP32 bits retained.
The final block is assigned positive infinity before four-byte radix selection;
negative-infinity blocks are excluded afterward. Arbitrary positive block
sizes, partial final blocks, lower-block tie order and zero requested blocks
are covered. Candidate selection has no global scratch buffer.

## Capture and concurrency

All launches and asynchronous memsets use the supplied stream. Eager and
captured calls execute the same path for the same interface arguments. There
are no allocations, frees, device-to-host copies, host synchronizations,
mutable global buffers, capture queries, events or lifetime caches. Concurrent
calls do not share internal state; callers provide nonoverlapping output arrays
or their own ordering, as with ordinary asynchronous CUDA kernels.

## Validation

Run the standard-library-only CPU model:

```
python src/ds41/kernels/k5/test_k510_model.py
```

It covers exact two/four-byte cutoff selection, contiguous-interval compaction,
output capacity for k below/above 512, all-equal/all-masked/infinite scores,
negative offsets, candidate FP32 precision and tails, split-counter overflow,
all non-NaN BF16 ordering encodings, the x256 fragment address mapping, async
stage ownership, capped-grid coverage and required BF16 rounding stages.

The CPU model passes 1,344 selection/candidate cases and the additional tile,
rounding, storage and counter tests. CUDA 12.8 C++17 compile-only preflight passes
sm_86, sm_89 and sm_120. On sm_89, ptxas reports 128 registers and 41,344 shared
bytes for tensor scoring, with zero spill loads/stores. Selection uses at most
6,156 shared bytes and 40 registers, also without spills. These are compiler
facts, not timing results. CPU models and compiler checks do not execute GPU code. Acceptance correctness, graph
replay, race/synchronization behavior and timing remain for the unchanged GPU
queue; no local GPU was used and no speedup is claimed here.
