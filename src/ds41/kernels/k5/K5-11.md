# K5-11: tensor scores with caller-storage radix selection

Base: `feature/ds41` at `c8c41ce1f0f4cd08969243d58294a850ee914fd0`.

This combines the 64-key BF16 tensor scorer from K5-02 commit
`9b8d285fab562d91d9f11a5ba208b98f79996f78` with the exact two-byte radix selector
and ascending emitter from K5-07 commit `466796657f0df8b68ca15615cebe9e28075bbfc5`.
The scorer body and complete caller-storage pipeline are byte-identical to
those respective sources. No allocator or cache from K5-02 is included.

The comparison control is K5-07's published RTX 4090 result, `score_us=310.1`
(`us_t16k=66.53`, `us_t128k=243.6`):
https://github.com/Jackwwg83/Strata-DS/issues/3#issuecomment-5994550843
The intended improvement is a hypothesis until this exact branch is tested.

## Scoring and selection semantics

Each 128-thread tensor CTA stages the 32-by-128 query, 64 keys, and weights.
Its four warps each compute 32 heads against 16 positions. FP32 accumulators
are rounded to BF16 before ReLU, each weighted head is rounded to BF16, then
heads are accumulated in order and rounded to BF16 again. These three rounding
points are unchanged. Tensor accumulation may differ from the reference warp
reduction within the task's explicit score tolerance; it is not claimed to be
bit-identical to that reduction. Calls with at most 512 keys keep the exact
reference-order small-input scorer. Partial tensor tiles zero-fill only their
out-of-range keys and never write beyond `scores[t]`. Masked scores are -inf.

`k` is clamped to `[0,t]`. Empty selection still computes scores; selecting all
positions emits directly. For fewer than 4096 keys, shared-only radix selection
handles the cutoff and ascending output. Larger selections use two distributed
histograms and 4096-key positional partitions. Exact cutoff ties select lower
positions, and ordered compaction emits ascending indices plus the offset.
Signed zero is canonicalized only for comparison; score bits are preserved.

Candidate-block selection is unchanged from K5-07. It computes block maxima on
demand and uses all four FP32 key bytes. It does not narrow arbitrary candidate
scores to BF16. The final block receives positive infinity, negative-infinity
blocks are dropped, and ties prefer lower block indices. Arbitrary positive
block sizes and final partial blocks use the same path.

## Metadata ownership, capacity, and exact restoration

Every produced FP32 score holds a BF16 encoding, including masked -inf, so its
low 16 bits are zero. Caller-owned score low halves temporarily hold metadata;
the high halves retain the complete numerical result.

1. The scorer is a separate kernel and completes on the supplied stream before
   any metadata kernel starts. Full-width score stores never overlap metadata
2. The state occupies low-halfword slots 0 through 4. Histogram CTA `p` owns
   slots `[8+1024*p, 8+1024*(p+1))`, with four disjoint halfwords per 64-bit bin
3. Only explicit PTX `ld.global.u16` accesses score high halves at `4*j+2`.
   Metadata loads/stores use `ld.global.u16`/`st.global.u16` at `4*j`. There are
   no full-width score accesses or global score atomics during metadata use
4. Choosers run after their histogram. The two-byte cutoff is final before
   count kernels reuse histogram storage. Partition `p` owns eight low-halfword
   slots at `8+8*p`, holding its 64-bit greater/equal counts
5. The prefix kernel loads each batch before overwriting that same batch.
   CTA barriers protect the shared scan. Each record has exactly one writer
6. The emitter reads stable state and prefixes and writes only `out_idx`.
   Its output positions are disjoint because they are exact positional ranks
7. A separate restoration kernel starts after every emission CTA completes.
   It zeros the complete metadata span. Other low halves were never modified;
   high halves were read-only. Every output score therefore regains its exact
   pre-metadata bits, including signed zero and BF16 NaN payload encodings

For `N>=4096`, define `C=ceil(N/4096)` and `P=min(C,256)`. Histograms require
`8+1024*P` low-halfword slots and counts require `8+8*C`. For `C=1`, both are
at most 1032, below `N>=4096`. For `C>=2`, the minimum possible N is
`4096*(C-1)+1`, which is at least both expressions. Therefore the restoration
span `8+max(1024*P,8*C)` always fits in the caller's N score slots, including
partial partitions and saturated histogram grids. Counts and prefixes are
64-bit; no allocation sizes are inferred from the benchmark's particular t/k.

Eager and captured calls use identical dispatch and launches. There are no
allocations, frees, host synchronization, device-host copies, events, capture
queries, global mutable scratch, or caches. Only the supplied stream is used.
Independent calls with disjoint caller-owned arrays share no mutable storage.
Normal CUDA ownership applies: callers must wait for stream completion before
accessing outputs or reusing them on unrelated streams.

## Validation

Run the CPU checks from the repository root:

```
python src/ds41/kernels/k5/test_selection_model.py
python src/ds41/kernels/k5/test_caller_storage.py
python src/ds41/kernels/k5/test_tensor_storage.py [generated-sm89.ptx]
```

These check exact selection/ties, all-FP32 candidate ordering, irregular sizes,
metadata bounds and phases, bit-exact restoration of all 65536 BF16 high-half
encodings, 64-bit counts, tensor layout/tails, source provenance, and stream/API
invariants. The optional PTX check verifies all eight metadata kernels retain
16-bit score accesses; the emitter's 32-bit stores target the index output.
They do not execute GPU math or validate WMMA rounding, races, or graph replay.

CUDA 12.8 C++17 compile-only preflight passes for sm_86, sm_89, and sm_120.
On sm_89, ptxas reports 46 registers and 32896 shared bytes for tensor scoring,
zero spills in every kernel, at most 2328 shared bytes for any selector, and
zero mutable global bytes. All kernels remain below the 99 KB limit. GPU
acceptance, non-default-stream graph replay, and timing await GPU validation.
