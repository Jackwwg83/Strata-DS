# K2-06: grouped output tiles

Based on `feature/ds41` commit `7b29dbd1d757479308a05d628e4146faf709c7b3`.

## Design

Large grids use 256-thread CTAs. Each CTA retains two independent 64x128
output tiles, sharing one 128x32 BF16 weight tile throughout each K step.
Weights are loaded as packed FP8, converted once, and reused by both row
groups. A loaded B MMA fragment also feeds both groups before it is replaced.
This halves FP8 weight conversion per output relative to a single 64-row CTA.
A four-CTA M-group traversal places CTAs using the same N weight slab next to
each other in the launch order. It is a bijective traversal, including the
last partial group, with no inter-CTA synchronization or global work counter.

The narrow-grid fallback uses a single 16x64 or 32x64 tile per CTA to preserve
parallelism. All paths use BF16 operands with FP32 `mma.m16n8k16` accumulation;
K remains ordered and is not split. Activation quantization matches the
reference power-of-two scale and CUDA E4M3 rounding. Weight conversion uses
CUDA's FP8 conversion and FP32 scaling before conversion to BF16.

Only `2*M*K` bytes of the guaranteed `4*M*K` caller workspace are used. There
are no allocations, host transfers, host synchronization, runtime queries,
weight caches, or device-global mutable state. Both kernels use the supplied
stream, including graph capture and replay.

## Cloud-only checks

- CUDA 12.8, C++17 compilation: passed for sm_86, sm_89, and sm_120
- sm_89 grouped kernel: 128 registers, 20,480 shared bytes, zero stack/spills
- sm_89 32x64 fallback: 64 registers, 7,680 shared bytes, zero stack/spills
- sm_89 16x64 fallback: 56 registers, 6,400 shared bytes, zero stack/spills
- `python src/ds41/kernels/k2/validate_grouped.py`: passed
  - Shared/vector ownership, matrix-address alignment, and output ownership
  - 1,681 launch-grid bijections, including partial M supergroups
  - Integer product models, M/N tails, and K=0 for every instantiation
  - 56,134 finite FP8/power-of-two values exactly represented as BF16
- Only the task's CI-FILES paths are changed

The CPU model does not execute CUDA instructions or validate GPU race freedom.
GPU numerical acceptance, graph replay, and timing are still for the authorized
RTX 4090 queue. No local GPU was used, and no speedup is claimed from compilation.
