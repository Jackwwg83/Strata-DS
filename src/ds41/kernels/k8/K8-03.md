# K8-03: one-CTA-per-token fused router

Base: feature/ds41 `75356589fcea9b33fe8d2a436354100dbcc4a85b`.
Only the K8 CI-FILES change. The interface and fixed acceptance test are unchanged.

## Algorithm and ownership

One 1024-thread CTA owns one token from input through the six final outputs.
Its 64 half-warps process six experts each, covering all 384 experts exactly
once. The token input is staged in shared memory. Each half-warp lane loads
one packed BF16 pair and maintains two independent FP32 accumulators.

The two accumulators correspond to reference lanes `2*lane` and `2*lane+1`.
They visit the same inputs in the same order and use explicit round-to-nearest
FP32 FMA. A half-warp shuffle tree of 8,4,2,1 on each parity, followed by
`even + odd`, reproduces the reference warp tree of 16,8,4,2,1. Consequently,
packing changes the load organization without changing the dot-product order.
BF16-aligned pointers that are not four-byte aligned use scalar pair loads;
the optimization does not impose a new pointer-alignment requirement.

After a block barrier, one warp selects six winners. Each lane scans its
12 experts and masks earlier winners. Pairwise reduction uses descending
biased score and ascending expert ID, including comparisons across lane and
half-warp boundaries. No cross-CTA synchronization or spin loop is involved.

The transform and bias addition are evaluated once in double for all 384
experts after the FP32 GEMV, matching the fixed acceptance reference. Selection
compares these stored double scores directly. The six selected unbiased
scores and their ordered sum/division also remain double until the final
float output. There is no approximate-ranking filter or discarded candidate
based on FP32 exp/log1p/sqrt.

### Correction of the first published candidate

The original `1b169b82e4593541b3d548b53811e470900f2742` used a rounded-score
comparison bound that was invalid after `expf` became subnormal or zero. For
legal logits -104 and -200 with biases 0 and 1e-24, it could rank the second
expert above the first even though the double reference ranks the first
higher. Merely guarding zero scores would leave the subnormal region exposed.
This revision removes that approximate comparison completely, rather than
asserting a bound over only part of the domain.

The regression uses BF16-realizable impulse dots and checks all six IDs and
normalized coefficients at 81 logits from -80 through -120. It places the pair
both first/second and fifth/sixth, crossing warp lanes, including the exact
-104/-200 case. Together these add 162 full-routing cases. The tests check
reference epsilon behavior and final FP32 rounding when a coefficient itself
is subnormal.

There are no host reads, allocations, frees, global workspaces, device-global
mutable state, default-stream operations, or capture-dependent paths. Every
call launches exactly one kernel on the supplied stream. Distinct calls own
their shared/register storage and their supplied output arrays.

## Offline validation

- CUDA 12.8 / C++17 compiles for sm_86, sm_89 and sm_120
- Unchanged acceptance test and ops.cu compiled for sm_89 and linked with
  the candidate using the available host linker; executable not run
- Aligned kernel: 27/27/51 registers respectively
- Unaligned fallback: 40/40/51 registers respectively
- Both kernels: 17,968 shared bytes, zero stack bytes and zero spills
- CPU model: 13,824 bitwise reference-versus-packed GEMV comparisons
- CPU model: 4,206 selection/normalization cases, including all m=1..8,
  all-equal and repeated ties, biased rounding collisions, cancellation,
  softplus's threshold, subnormal logits, underflow, and large values
- CPU ownership model: exactly one producer per expert and complete dot coverage
- No fixed header, acceptance test, dependency or build file changes

Run the CPU-only model from the repository root:

```sh
g++ -O3 -std=c++17 -ffp-contract=off \
  src/ds41/kernels/k8/test_fused_router_model.cpp -o /tmp/k8_model
/tmp/k8_model
```

These are compile, source and CPU-model checks. They do not establish GPU
correctness, CUDA graph capture/replay, race freedom or performance. The GPU
queue is offline at publication; its unchanged acceptance test remains the
gate for numerical parity and ranking.

## Performance hypothesis and risk

This candidate removes host selection/readbacks and all inter-kernel launches
and global scratch traffic. All-expert double transforms add work compared
with the flawed first candidate, while simplifying the selection loop.
Packed loads and 64 concurrent expert reductions
aim to keep each participating SM busy. However, m=1..8 yields only 1..8 CTAs,
and each token reads the whole weight matrix. Low SM coverage and the lack of
cross-token weight reuse may outweigh fusion. This is a distinct experiment
from a tiled GEMV plus selection; it is not a measured speedup.
